XWiki sobre Tomcat en Debian 12

Referencia de laboratorio · Administración y Configuración Cliente/Servidor

Esta guía despliega XWiki, un wiki colaborativo escrito en Java, sobre el Tomcat que instalaste en la práctica anterior y con MySQL como base de datos. Es la primera aplicación Java del curso: aprenderás qué es un archivo .war, cómo se despliega y cómo se conecta con la base de datos. Al final tendrás tu wiki en http://IP:8080/xwiki.

Tus datos

Escribe la IP de tu VM (paso 10.3) y la contraseña que usarás para el usuario xwiki de MySQL. Los comandos de la guía se actualizan con ellos.

http://192.168.1.50:8080/xwiki

Antes de empezar

Esta práctica es la continuación de la guía Apache Tomcat en Debian 12. Se asume que ya tienes:

  • Tomcat 10.1 instalado en /opt/tomcat, funcionando como servicio tomcat con el usuario tomcatuser.
  • Java (OpenJDK 17) instalado con default-jdk.
  • Un servidor MySQL o MariaDB funcionando en la misma VM.
  • La VM con al menos 3 GB de RAM (XWiki es más pesado que WordPress) y acceso a internet.

Es la primera aplicación Java que instalamos en el curso. Por eso, antes de los comandos hay cuatro conceptos: qué es el JDK, qué es un archivo .war, cómo despliega Tomcat una aplicación y por qué se usa la IP y no localhost.

Conceptos previos

Léelos antes de instalar: explican lo que vas a hacer en cada paso.

A. Recordatorio: ¿qué es el JDK?

Java es un lenguaje compilado a bytecode. El código fuente (.java) no se ejecuta directo: primero se compila a un formato intermedio (.class) y ese formato lo ejecuta la máquina virtual de Java (JVM). Así un mismo programa corre en cualquier sistema que tenga una JVM.

JVM
Java Virtual Machine. El programa que ejecuta el bytecode. Es lo que ves como proceso java en ps o ss.
JRE
Java Runtime Environment. La JVM más las bibliotecas estándar: lo necesario para ejecutar programas Java.
JDK
Java Development Kit. El JRE más las herramientas para desarrollar: el compilador javac, jar, depuradores, etc.
OpenJDK
La implementación libre de Java. Es la que instala Debian 12 con default-jdk (versión 17).
JAVA_HOME
Variable que indica dónde está instalado Java. En la guía de Tomcat la pusimos en el servicio: /usr/lib/jvm/default-java.

¿Y Tomcat qué tiene que ver? Tomcat también es un programa escrito en Java: cuando arranca el servicio, en realidad arranca una JVM, y dentro de ella corren todas las aplicaciones .war que despliegues. Por eso sin Java no hay Tomcat, y por eso la memoria que le damos a XWiki se configura como memoria de la JVM (paso 8).

XWiki 17 necesita Java 17 o superior, justo lo que trae Debian 12.

B. ¿Qué es un archivo .war?

Un .war (Web Application Archive) es la aplicación web Java completa empaquetada en un solo archivo. Por dentro es un .zip con una estructura de carpetas fija que todos los servidores Java entienden. Lo puedes abrir con unzip igual que cualquier zip.

Compáralo con WordPress: ahí copiaste a /var/www/html una carpeta llena de archivos .php que Apache lee e interpreta en cada visita. En Java la aplicación ya viene compilada (bytecode en .class y .jar) y empaquetada: tú no ves el código fuente, solo despliegas el paquete.

Estructura de un .war (ejemplo: XWiki)

xwiki.war
├── META-INF/            información del paquete
├── WEB-INF/             zona privada: no se puede ver desde el navegador
│   ├── web.xml          descriptor: le dice a Tomcat cómo cargar la app
│   ├── lib/             bibliotecas .jar (aquí va el driver de MySQL)
│   ├── classes/         clases .class propias de la aplicación
│   ├── hibernate.cfg.xml   conexión a la base de datos
│   ├── xwiki.cfg           configuración general de XWiki
│   └── xwiki.properties    configuración (directorio de datos, etc.)
├── resources/           imágenes, CSS y JavaScript públicos
├── skins/               apariencia del sitio
└── templates/           plantillas de las páginas
.jar
Java Archive. Un zip con clases Java: una biblioteca o un programa. Un .war contiene muchos .jar dentro de WEB-INF/lib.
.war
Un zip con una aplicación web completa, lista para un servidor como Tomcat.
WEB-INF
Carpeta protegida: Tomcat nunca la entrega al navegador. Ahí van la configuración y las contraseñas de la base de datos.

C. ¿Cómo despliega Tomcat una aplicación?

Desplegar es poner la aplicación en el servidor para que empiece a atender peticiones. Tomcat vigila la carpeta /opt/tomcat/webapps: cada archivo .war o carpeta que encuentra ahí es una aplicación.

Hay tres formas de desplegar:

FormaCómo funciona¿La usamos?
Copiar el .warCopias xwiki.war a webapps/ y Tomcat lo descomprime solo (autoDeploy).No
Descomprimir a manoTú creas webapps/xwiki/ y descomprimes ahí el .war.Sí
Manager webSubes el .war desde la página del Manager de Tomcat (/manager/html).No

¿Por qué a mano? Porque XWiki no puede arrancar con la configuración de fábrica: antes de que Tomcat la cargue hay que agregar el driver de MySQL en WEB-INF/lib y editar dos archivos dentro de WEB-INF. Si copiaras el .war directo, Tomcat la arrancaría de inmediato con la configuración equivocada. Por eso: detener Tomcat → descomprimir → configurar → arrancar.

La carpeta especial webapps/ROOT es la que responde en la raíz (http://IP:8080/): es la página del gato que viste al instalar Tomcat.

D. ¿Por qué http://IP:8080 y no localhost?

localhost (dirección 127.0.0.1) no es un servidor en particular: significa «esta misma máquina», la máquina donde se escribe. Cada equipo tiene su propio localhost.

En el laboratorio hay dos equipos: la PC anfitrión (Windows, donde está el navegador) y la VM Debian (donde está Tomcat). Si en el navegador de Windows escribes localhost:8080, la petición nunca sale de Windows: busca un Tomcat en Windows y no lo encuentra. Para llegar a la VM hay que usar su IP.

Desde dónde abres el navegadorDirecciónPor qué
Dentro de la VM (o con curl en la VM)http://localhost:8080/xwikiEl navegador y Tomcat están en la misma máquina.
PC anfitrión, VM en Adaptador puentehttp://IP-de-la-VM:8080/xwikiLa VM tiene su propia IP en la red del laboratorio.
Otra PC del laboratoriohttp://IP-de-la-VM:8080/xwikiIgual que el anterior: así lo verían tus compañeros.
PC anfitrión, VM en NAThttp://localhost:8080/xwikiSolo si en VirtualBox reenvías el puerto 8080 del anfitrión al 8080 de la VM.

Fíjate en el detalle: en el paso 6 configurarás XWiki para conectarse a MySQL en localhost. Ahí sí es correcto, porque XWiki (dentro de Tomcat) y MySQL están en la misma VM. La pregunta siempre es: ¿desde qué máquina sale la conexión?

Para que la IP funcione, Tomcat debe escuchar en todas las interfaces (0.0.0.0 o *), no solo en 127.0.0.1. Lo comprobarás en el paso 10.2.

E. ¿Qué es XWiki?

XWiki es un wiki colaborativo de código abierto, parecido a Wikipedia o a Confluence: los usuarios crean y editan páginas desde el navegador, suben archivos, comentan y se organizan por espacios. Está hecho en Java y se distribuye como .war. Guarda las páginas en MySQL y los archivos adjuntos e índices en un directorio del disco.

Instalación

Ejecuta los pasos en orden dentro de la VM. Los valores en color se toman de «Tus datos».

1. Verificar los requisitos

1.1

Java y Tomcat

Confirmar que Java responde y que el servicio Tomcat de la guía anterior está activo.

$java -version
$sudo systemctl status tomcat --no-pager

Debe aparecer openjdk version "17..." y active (running).

1.2

Servidor de base de datos

Comprobar que MySQL (o MariaDB) está activo.

$sudo systemctl status mysql --no-pager

En MariaDB el servicio se llama mariadb, pero mysql funciona como alias.

1.3

Memoria disponible

Revisar cuánta RAM tiene la VM.

$free -h

En la columna total de «Mem» deben aparecer 3 GB o más. Si hay menos, apaga la VM y súbele la memoria en VirtualBox.

2. Instalar herramientas

2.1

unzip, wget y curl

unzip sirve para abrir el .war, wget para descargar archivos y curl para probar la aplicación desde la terminal.

$sudo apt update
$sudo apt install unzip wget curl -y

3. Crear la base de datos

3.1

Entrar a MySQL

Abrir la consola de MySQL como administrador.

$sudo mysql

Si te pide contraseña o marca «Access denied», usa mysql -u root -p y escribe la contraseña de root que pusiste al instalar MySQL.

3.2

BD y usuario xwiki

Crear la base de datos con codificación utf8mb4 y un usuario exclusivo para la aplicación.

mysql>CREATE DATABASE xwiki DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;
mysql>CREATE USER 'xwiki'@'localhost' IDENTIFIED BY 'Xwiki#Lab2026';
mysql>GRANT ALL PRIVILEGES ON *.* TO 'xwiki'@'localhost';
mysql>FLUSH PRIVILEGES;
mysql>EXIT;

utf8mb4_bin es la codificación que exige XWiki (acentos, ñ y emojis). XWiki pide privilegios en *.* porque cada subwiki es una base de datos nueva; en producción se restringen.

La contraseña debe ser la misma que pondrás en el paso 6. Si MySQL responde «Your password does not satisfy the current policy», usa una más compleja (mayúscula, minúscula, número y símbolo) y actualiza «Tus datos».

3.3

Probar el usuario

Entrar con el usuario nuevo para confirmar la contraseña y ver la base de datos.

$mysql -u xwiki -p -e 'SHOW DATABASES;'

Escribe la contraseña del paso 3.2. En la lista debe aparecer xwiki.

4. Descargar XWiki

4.1

Descargar el .war

Descargar la versión LTS (soporte extendido) de XWiki en /tmp y guardarla con el nombre corto xwiki.war.

$cd /tmp
$wget https://maven.xwiki.org/releases/org/xwiki/platform/xwiki-platform-distribution-war/17.10.14/xwiki-platform-distribution-war-17.10.14.war -O xwiki.war

Pesa varios cientos de MB, puede tardar. Se usa la rama 17.10 porque es la LTS y la primera que funciona en Tomcat 10 (usa Jakarta EE). Las versiones 16.x o anteriores no funcionan en Tomcat 10. Para una versión más nueva de la rama 17.10, consúltala en xwiki.org/xwiki/bin/view/Download y cambia el número en los dos lugares de la URL.

4.2

Ver qué hay dentro

Comprobar que el .war es un zip y listar sus archivos de configuración, sin descomprimirlo.

$file xwiki.war
$unzip -l xwiki.war 'WEB-INF/*.xml' 'WEB-INF/*.cfg' 'WEB-INF/*.properties'
$unzip -l xwiki.war 'WEB-INF/lib/*' | wc -l

file responde «Zip archive» o «Java archive». El último comando cuenta las bibliotecas .jar que trae: son cientos. Toda la aplicación viaja en este único archivo.

5. Desplegar (descomprimir en webapps)

5.1

Detener Tomcat

Se detiene para que no cargue la aplicación a medias mientras la configuras.

$sudo systemctl stop tomcat
5.2

Descomprimir en webapps/xwiki

Crear la carpeta de la aplicación y extraer ahí el contenido del .war.

$sudo mkdir /opt/tomcat/webapps/xwiki
$sudo unzip -q /tmp/xwiki.war -d /opt/tomcat/webapps/xwiki

El nombre de la carpeta, xwiki, define la URL: http://IP:8080/xwiki. Si la llamaras wiki, la URL sería /wiki. -q solo evita que liste miles de archivos.

5.3

Revisar el resultado

Ver las aplicaciones que tiene Tomcat y el contenido de WEB-INF.

$ls /opt/tomcat/webapps
$ls /opt/tomcat/webapps/xwiki/WEB-INF

En webapps verás xwiki junto a las que trae Tomcat (ROOT, docs, examples, manager…). En WEB-INF están los archivos que vas a editar.

6. Conectar XWiki con MySQL

6.1

Driver JDBC

Descargar el conector de MySQL para Java y copiarlo a las bibliotecas de la aplicación.

JDBC (Java Database Connectivity) es la forma estándar en que un programa Java habla con una base de datos. El driver es un .jar que traduce entre Java y el protocolo de MySQL. Es el equivalente al paquete php-mysql que instalaste para WordPress. XWiki no lo trae incluido.

$cd /tmp
$wget https://repo1.maven.org/maven2/com/mysql/mysql-connector-j/26.7.0/mysql-connector-j-26.7.0.jar
$sudo cp mysql-connector-j-26.7.0.jar /opt/tomcat/webapps/xwiki/WEB-INF/lib/

Este driver también se conecta a MariaDB 10.11, el que trae Debian 12.

6.2

Editar hibernate.cfg.xml

Hibernate es la biblioteca que usa XWiki para guardar datos. En este archivo se le indica a qué base de datos conectarse.

$sudo nano /opt/tomcat/webapps/xwiki/WEB-INF/hibernate.cfg.xml

De fábrica, XWiki usa HSQLDB, una base de datos de prueba que vive en un archivo. Busca con Ctrl+W el texto default database. Justo debajo de ese comentario están las 4 líneas activas:

Antes: líneas activas (HSQLDB)

<!-- Configuration for the default database. ... -->
<property name="hibernate.connection.url">jdbc:hsqldb:file:${environment.permanentDirectory}/database/xwiki_db;shutdown=true</property>
<property name="hibernate.connection.username">sa</property>
<property name="hibernate.connection.password"></property>
<property name="hibernate.connection.driver_class">org.hsqldb.jdbcDriver</property>

Reemplaza solo esas 4 líneas por estas:

Después: hibernate.cfg.xml (MySQL)

<property name="hibernate.connection.url">jdbc:mysql://localhost/xwiki?useSSL=false&amp;allowPublicKeyRetrieval=true</property>
<property name="hibernate.connection.username">xwiki</property>
<property name="hibernate.connection.password">Xwiki#Lab2026</property>
<property name="hibernate.connection.driver_class">com.mysql.cj.jdbc.Driver</property>

Guarda con Ctrl+O, Enter y sal con Ctrl+X.

localhost/xwiki
Servidor y base de datos. Es localhost porque MySQL está en la misma VM que Tomcat (concepto D).
useSSL=false
Sin cifrado: la conexión no sale de la VM.
allowPublicKeyRetrieval
Necesario en MySQL 8 para autenticarse sin SSL. Sin él aparece «Public Key Retrieval is not allowed».
&amp;
En XML el símbolo & se escribe &amp;. Escribirlo solo rompe el archivo.

No comentes el bloque con <!-- -->: tiene comentarios dentro y el XML queda roto. Solo cambia esas 4 líneas. Más abajo en el archivo hay otros bloques de MySQL, MariaDB y PostgreSQL que ya están comentados: no los toques.

6.3

Verificar el cambio

Las primeras 4 líneas de conexión que aparezcan deben ser las tuyas, con mysql.

$grep -n 'hibernate.connection' /opt/tomcat/webapps/xwiki/WEB-INF/hibernate.cfg.xml | head -4

7. Directorio permanente

7.1

Crear el directorio de datos

Aquí XWiki guarda los archivos adjuntos, el índice de búsqueda y las extensiones instaladas. Debe ser de tomcatuser para que Tomcat pueda escribir.

$sudo mkdir -p /var/lib/xwiki/data
$sudo chown -R tomcatuser:tomcatuser /var/lib/xwiki
7.2

Configurar xwiki.properties

Activar la línea environment.permanentDirectory, que de fábrica viene comentada con #.

$sudo sed -i 's|^# environment.permanentDirectory = .*|environment.permanentDirectory = /var/lib/xwiki/data/|' /opt/tomcat/webapps/xwiki/WEB-INF/xwiki.properties
$grep -n '^environment.permanentDirectory' /opt/tomcat/webapps/xwiki/WEB-INF/xwiki.properties

sed -i edita el archivo sin abrirlo: busca la línea que empieza con # environment.permanentDirectory y la reemplaza sin el #. El grep debe mostrar la línea activa. Si no se configura, XWiki usa una carpeta temporal que se puede borrar, y perderías las extensiones instaladas.

8. Memoria de la JVM

8.1

Crear setenv.sh

Al arrancar, Tomcat lee automáticamente bin/setenv.sh si existe. Ahí se le pasan opciones a la JVM.

$sudo nano /opt/tomcat/bin/setenv.sh

/opt/tomcat/bin/setenv.sh

#!/bin/sh
# Memoria de la JVM de Tomcat (XWiki necesita más que el valor por defecto)
CATALINA_OPTS="$CATALINA_OPTS -Xms512m -Xmx1536m"
CATALINA_OPTS="$CATALINA_OPTS -Dfile.encoding=UTF-8"
CATALINA_OPTS="$CATALINA_OPTS -Djava.security.egd=file:/dev/./urandom"
export CATALINA_OPTS
-Xms512m
Memoria inicial que reserva la JVM.
-Xmx1536m
Memoria máxima. Si XWiki la rebasa: error «OutOfMemoryError: Java heap space».
file.encoding
Fuerza UTF-8 para acentos y ñ.
java.security.egd
Evita que el arranque se congele esperando números aleatorios en las VMs.

La VM necesita más RAM que -Xmx, porque Debian y MySQL también ocupan memoria: con 3 GB en la VM, 1536 MB para Java es razonable.

8.2

Permisos de setenv.sh

Hacerlo ejecutable y de tomcatuser, igual que los demás scripts de bin/.

$sudo chmod +x /opt/tomcat/bin/setenv.sh
$sudo chown tomcatuser:tomcatuser /opt/tomcat/bin/setenv.sh

9. Permisos de la aplicación

9.1

Propietario tomcatuser

Lo que descomprimiste y copiaste con sudo quedó a nombre de root. Tomcat corre como tomcatuser y necesita poder leer y escribir ahí.

$sudo chown -R tomcatuser:tomcatuser /opt/tomcat/webapps/xwiki

10. Arrancar y verificar

10.1

Iniciar Tomcat y seguir el log

Arrancar el servicio y observar en vivo cómo carga la aplicación.

$sudo systemctl start tomcat
$sudo tail -f /opt/tomcat/logs/catalina.out

Espera el mensaje Server startup in [...] milliseconds. La primera vez tarda de 1 a 3 minutos. Sal del log con Ctrl+C: Tomcat sigue corriendo.

10.2

Puerto y prueba local

Ver en qué interfaces escucha Tomcat y probar la aplicación desde la propia VM.

$sudo ss -tlnp | grep ':8080 '
$curl -sI http://localhost:8080/xwiki/ | head -1

En ss debe verse *:8080 o 0.0.0.0:8080: escucha en todas las interfaces, no solo en localhost, así que también responde por la IP. curl debe devolver HTTP/1.1 302 o 200.

10.3

Obtener la IP de la VM

Esta es la dirección que vas a escribir en el navegador del anfitrión.

$hostname -I

Muestra las IPs de la VM. La que empieza igual que la red del laboratorio (por ejemplo 192.168…) es la de la tarjeta en puente. Escríbela en «Tus datos».

10.4

Abrir en el navegador

Desde la PC anfitrión (concepto D).

Navegador de la PC anfitrión

http://192.168.1.50:8080/xwiki

11. Asistente de instalación (en el navegador)

11.1

Distribution Wizard

La primera vez, XWiki abre un asistente que termina la instalación. Necesita internet: descarga la interfaz desde extensions.xwiki.org.

  1. Espera a que termine la barra de inicialización y da clic en Continue.
  2. Admin user: crea la cuenta de administrador (usuario, contraseña y correo). Anótala. Da clic en Register and login y luego en Continue.
  3. Flavor: elige XWiki Standard Flavor y da clic en Install this flavor, luego en Install.
  4. Espera a que termine: descarga e instala cientos de extensiones (5 a 15 minutos, según la red). No cierres la pestaña.
  5. En los siguientes pasos da clic en Continue hasta llegar a la página principal del wiki.

Si la instalación del flavor marca error, revisa que la VM tenga internet: ping -c 3 extensions.xwiki.org.

11.2

Ver las tablas que se crearon

XWiki creó solo todas sus tablas en la base de datos de MySQL. Compruébalo.

$sudo mysql -e 'USE xwiki; SHOW TABLES;'

Verás tablas como xwikidoc (las páginas) y xwikiattachment (los adjuntos). Hibernate las genera a partir de los archivos .hbm.xml que viste en el paso 6.
