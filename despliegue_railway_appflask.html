Despliegue de una aplicación Flask en Railway

Guía práctica desde la creación del entorno virtual hasta el primer despliegue exitoso con GitHub, Gunicorn y Procfile.

Propósito de la práctica

Preparar una aplicación web desarrollada con Python Flask para desplegarla en Railway, utilizando un entorno virtual, archivo requirements.txt, .gitignore, control de versiones con Git/GitHub, Gunicorn como servidor WSGI y un archivo Procfile para indicar el comando de inicio.

Conceptos clave

Entorno virtual: carpeta aislada donde se instalan las librerías de Python necesarias para una aplicación específica, sin afectar las librerías globales instaladas en Windows.

requirements.txt: archivo que guarda la lista de dependencias de Python que Railway debe instalar automáticamente al construir la aplicación.

.gitignore: archivo que indica a Git qué carpetas o archivos no deben subirse a GitHub, por ejemplo el entorno virtual.

Gunicorn: servidor WSGI usado para ejecutar aplicaciones Flask en producción. Railway lo utiliza para arrancar la aplicación en Linux.

Procfile: archivo de texto sin extensión que le indica a Railway cómo iniciar la aplicación.

Arquitectura básica del despliegue

Elemento Función Ejemplo usado
Aplicación Flask Contiene rutas, vistas, templates, conexión a base de datos y lógica principal. miapp.py
Objeto Flask Instancia que Gunicorn debe cargar para iniciar la aplicación. miproyectoApp
Entorno virtual Aísla las dependencias del proyecto. env/
Railway Plataforma cloud donde se construye y ejecuta la aplicación. Deploy from GitHub repo
Nota: En esta guía se usa como ejemplo una app cuyo archivo principal es miapp.py y cuyo objeto Flask se llama miproyectoApp. Si tu archivo u objeto tienen otro nombre, debes modificar el comando de Gunicorn.

1. Ubicarse en la carpeta del proyecto

Antes de crear el entorno virtual, se debe abrir la carpeta del proyecto en Visual Studio Code o entrar a ella desde la terminal.

1.1
Entra a la carpeta del proyecto desde PowerShell. Ajusta la ruta si tu proyecto está en otra ubicación.
cd C:\Users\Adán\Desktop\miapp
1.2
Verifica que aparezcan los archivos principales del proyecto.
dir
Nota: En Visual Studio Code también puedes abrir la carpeta desde File → Open Folder y luego abrir la terminal integrada con Terminal → New Terminal.

2. Crear el entorno virtual

El entorno virtual se crea dentro del proyecto, pero no debe subirse a GitHub.

2.1
Crea un entorno virtual llamado env.
python -m venv env
2.2
Activa el entorno virtual en PowerShell.
.\env\Scripts\Activate.ps1
2.3
Si PowerShell bloquea la activación, permite scripts para el usuario actual.
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
2.4
Activa nuevamente el entorno virtual después de cambiar la política.
.\env\Scripts\Activate.ps1
2.5
Alternativa para CMD si no se desea usar PowerShell.
env\Scripts\activate
Resultado esperado: La terminal debe mostrar algo parecido a (env) al inicio de la línea.

3. Instalar dependencias dentro del entorno virtual

Con el entorno virtual activo, se instalan las librerías utilizadas por la aplicación Flask.

3.1
Instala Flask, login, correo, MySQL y Gunicorn.
pip install flask flask-login flask-mail flask-mysqldb pymysql gunicorn
3.2
Verifica las librerías instaladas.
pip list
3.3
Agregar PyMySQL al inicio del archivo miapp.py, antes de importar flask_mysqldb.
import pymysql pymysql.install_as_MySQLdb()
Nota: Si la app usa otras librerías, también deben instalarse dentro del entorno virtual antes de generar el archivo requirements.txt.

4. Generar requirements.txt

Este archivo permite que Railway instale las mismas dependencias durante el despliegue.

4.1
Genera el archivo requirements.txt a partir de las librerías instaladas.
pip freeze > requirements.txt
4.2
Muestra el contenido del archivo requirements.txt.
type requirements.txt

Ejemplo de requirements.txt usado en la práctica

blinker==1.8.2 click==8.1.8 colorama==0.4.6 Flask==3.0.3 Flask-Login==0.6.3 Flask-Mail==0.10.0 Flask-MySQLdb==2.0.0 gunicorn==23.0.0 importlib_metadata==8.5.0 itsdangerous==2.2.0 Jinja2==3.1.6 MarkupSafe==2.1.5 mysqlclient==2.2.4 packaging==26.2 Werkzeug==3.0.6 zipp==3.20.2
Diferencia importante: pip freeze > requirements.txt guarda las librerías instaladas. En cambio, pip install -r requirements.txt instala las librerías listadas en ese archivo.

5. Crear el archivo .gitignore

El entorno virtual no debe subirse a GitHub. Para evitarlo, se crea un archivo .gitignore en la raíz del proyecto.

5.1
Crea el archivo .gitignore con las exclusiones principales.
@" env/ __pycache__/ *.pyc .env "@ | Out-File .gitignore
5.2
Verifica que el archivo exista en la raíz del proyecto.
dir

Contenido esperado de .gitignore

env/ __pycache__/ *.pyc .env
Importante: El archivo .gitignore no se ejecuta como comando. Es un archivo de texto que se guarda en la raíz del proyecto, al mismo nivel que requirements.txt y miapp.py.

6. Verificar que Git ignore el entorno virtual

Antes de hacer commit, se revisa que Git no intente subir la carpeta env.

6.1
Revisa el estado del repositorio.
git status
Resultado esperado: Deben aparecer archivos como .gitignore y requirements.txt, pero no debe aparecer env/.
6.2
Si por error Git ya empezó a rastrear env, quítalo del índice sin borrarlo de tu computadora.
git rm -r --cached env

7. Crear el Procfile para Railway

Railway necesita saber cómo iniciar la aplicación. Como el archivo se llama miapp.py y no app.py o main.py, conviene crear un Procfile.

7.1
Crea el archivo Procfile con el comando de inicio. Debe llamarse Procfile, sin extensión .txt.
@" web: gunicorn miapp:miproyectoApp "@ | Out-File Procfile -Encoding ascii
7.2
Verifica que el archivo Procfile exista en la raíz del proyecto.
dir

Contenido esperado del Procfile

web: gunicorn miapp:miproyectoApp
Explicación: miapp corresponde al archivo miapp.py sin la extensión. miproyectoApp corresponde al objeto Flask creado dentro del archivo.

8. Crear base de datos MySQL en Railway e importar respaldo SQL

En esta sección se crea el servicio MySQL en Railway, se importa el respaldo miapp.sql y se configuran las variables de entorno para conectar Flask con la base de datos en producción.

8.1
Dentro del proyecto de Railway crear un nuevo servicio de MySQL.
New → Database → MySQL
8.2
Abrir el servicio MySQL y entrar a la sección de conexión pública.
MySQL → Connect → Public Network
8.3
Abrir PowerShell o la terminal de VS Code y entrar a la carpeta donde se encuentra el respaldo miapp.sql.
cd /static/sql
8.4
Importar el respaldo SQL usando MySQL 8 y conexión segura SSL.
Get-Content miapp.sql | & "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -h kodama.proxy.rlwy.net -u root -p --port 38862 --protocol=TCP --ssl-mode=REQUIRED railway
8.5
Cuando el sistema solicite la contraseña, pegar la contraseña MYSQLPASSWORD proporcionada por Railway.
Enter password: ***************
8.6
Verificar en Railway que las tablas se hayan importado correctamente.
MySQL → Database → Data

9. Hacer commit y push a GitHub

Después de crear requirements.txt, .gitignore y Procfile, se suben los cambios a GitHub.

9.1
Agrega los archivos al commit.
git add .
9.2
Crea el commit.
git commit -m "Preparar despliegue Flask en Railway"
9.3
Sube los cambios al repositorio remoto.
git push
Alternativa para clase: Después de preparar los archivos, los estudiantes pueden hacer commit y push desde la interfaz gráfica de Visual Studio Code usando Source Control, Commit y Sync Changes.

10. Crear proyecto en Railway desde GitHub

Una vez que el repositorio está actualizado en GitHub, Railway puede desplegarlo automáticamente.

10.1
En Railway selecciona esta opción.
New Project → Deploy from GitHub repo
10.2
Si no aparece el repositorio, autoriza el acceso desde GitHub App.
Configure GitHub App → Repository access → Only select repositories → miapp → Save → Refresh
10.3
Selecciona el repositorio de la aplicación.
adanlopez6589/miapp
Nota: Railway puede asignar un nombre automático al proyecto. Ese nombre puede cambiarse en Project Settings → General → Name.
10.4
Configurar las variables de entorno en el servicio Flask de Railway.
MYSQLHOST=kodama.proxy.rlwy.net MYSQLUSER=root MYSQLPASSWORD=contraseña_generada_por_railway MYSQLDATABASE=railway MYSQLPORT=38862
10.5
Modificar config.py para leer las variables desde Railway.
MYSQL_HOST = os.environ.get('MYSQLHOST') MYSQL_USER = os.environ.get('MYSQLUSER') MYSQL_PASSWORD = os.environ.get('MYSQLPASSWORD') MYSQL_DB = os.environ.get('MYSQLDATABASE') MYSQL_PORT = int(os.environ.get('MYSQLPORT', 3306))
10.6
Agregar temporalmente impresiones de diagnóstico para verificar que Railway está leyendo las variables correctamente. Despues de la linea: miproyectoApp.config.from_object(config['mail'])
print("HOST:", miproyectoApp.config['MYSQL_HOST']) print("USER:", miproyectoApp.config['MYSQL_USER']) print("DB:", miproyectoApp.config['MYSQL_DB']) print("PORT:", miproyectoApp.config['MYSQL_PORT'])
10.7
Guardar cambios, realizar commit y enviar nuevamente el proyecto a GitHub.
git add . git commit -m "Configuracion MySQL Railway" git push origin main
10.8
Aplicar los cambios pendientes del servicio en Railway.
Deploy Changes
10.9
Reiniciar o volver a desplegar el servicio Flask.
Deployments → Redeploy
10.10
Verificar en los logs que Flask ya detecte correctamente la conexión MySQL.
HOST: kodama.proxy.rlwy.net USER: root DB: railway PORT: 38862
10.11
Generar el dominio público para acceder a la aplicación Flask desde Internet.
Networking → Generate Domain
10.12
Abrir la aplicación desplegada en el navegador.
https://miapp-production-e147.up.railway.app/
Resultado esperado: La aplicación Flask debe quedar desplegada correctamente en Railway con conexión funcional a MySQL y acceso desde navegador mediante dominio público HTTPS.

Conclusión didáctica

Esta práctica permite observar la transición entre una aplicación Flask ejecutada localmente y una aplicación preparada para producción en la nube. El punto central no es solo subir código, sino comprender la función de cada archivo: el entorno virtual organiza dependencias, requirements.txt permite reproducirlas, .gitignore evita subir archivos innecesarios, Procfile define el inicio del servicio y Gunicorn ejecuta Flask en Railway.

Material didáctico para práctica de laboratorio: Flask, GitHub, Gunicorn y Railway.
