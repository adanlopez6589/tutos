Instalación y configuración básica de Postfix y Dovecot en Debian 12

Servidor SMTP con Postfix y acceso a buzones con Dovecot.

Propósito de la práctica

Instalar y configurar de manera básica un servidor de correo local en Debian 12 utilizando Postfix como servidor SMTP y Dovecot como servidor IMAP/POP3, con el fin de comprender la función de cada componente dentro del modelo cliente-servidor.

Arquitectura real del sistema de correo (flujo completo)

En un sistema de correo electrónico moderno intervienen varios agentes especializados que trabajan en conjunto para garantizar el envío, transporte, validación y entrega de los mensajes.

Flujo del correo:
MUA → MSA → MTA → MTA (Internet) → MDA → Dovecot → MUA

Agentes del sistema de correo

MUA (Mail User Agent): Es el cliente de correo utilizado por el usuario final para redactar, enviar y leer mensajes. Ejemplo: Thunderbird.

MSA (Mail Submission Agent): Recibe el correo desde el cliente (MUA), valida credenciales y prepara el mensaje antes de enviarlo al servidor de transporte. Generalmente opera en el puerto 587.

MTA (Mail Transfer Agent): Es el encargado de enrutar y transferir los correos entre servidores utilizando SMTP. Puede pasar por varios MTAs hasta llegar al destino. Ejemplo: Postfix.

MDA (Mail Delivery Agent): Recibe el correo del MTA y lo almacena en el buzón del usuario (Maildir). Aquí es donde realmente “llega” el correo al servidor destino.

Servidor de acceso (Dovecot): Permite al usuario consultar su buzón mediante IMAP o POP3.

Elementos adicionales de la imagen (nivel producción)

IP Warmup(Acondicionamiento de la IP): Es el proceso de aumentar gradualmente el volumen de envío de correos desde una dirección IP nueva para generar reputación y evitar que los mensajes sean marcados como spam.

Email Throttling(Control de envío de correos): Técnica que controla la cantidad de correos enviados por unidad de tiempo para evitar bloqueos por parte de servidores receptores o sistemas anti-spam.

DKIM (DomainKeys Identified Mail, Autenticación de correo por firma digital del dominio): Método de autenticación que firma digitalmente los correos electrónicos para verificar que el mensaje no ha sido alterado y que proviene del dominio legítimo.

Fundamentos de protocolos y agentes de correo

SMTP (Simple Mail Transfer Protocol) es el protocolo utilizado para el envío de correos electrónicos entre servidores y desde clientes hacia el servidor. Es el protocolo que utiliza Postfix para transferir mensajes.

IMAP (Internet Message Access Protocol) es el protocolo que permite a los usuarios acceder y gestionar sus correos directamente en el servidor sin descargarlos completamente. Es el método más utilizado actualmente para consultar el correo desde múltiples dispositivos.

POP3 (Post Office Protocol versión 3) es un protocolo que permite descargar los correos del servidor al equipo local, generalmente eliminándolos del servidor después de la descarga.

En la arquitectura de correo electrónico intervienen distintos agentes:

MTA (Mail Transfer Agent): Es el encargado de enviar y enrutar los correos entre servidores. En esta práctica, Postfix cumple esta función utilizando SMTP.

MDA (Mail Delivery Agent): Es el encargado de entregar el correo al buzón del usuario dentro del sistema. En esta práctica, la entrega se realiza en formato Maildir, donde cada mensaje se almacena como un archivo individual.

MUA (Mail User Agent): Es el cliente de correo que utiliza el usuario final para leer y enviar mensajes. En esta práctica, Thunderbird cumple este rol.

Servidor de acceso a correo: Permite que el usuario consulte sus mensajes almacenados en el servidor mediante protocolos como IMAP o POP3. En esta práctica, Dovecot cumple esta función.

Conceptos clave

Componente Función Protocolos relacionados
Postfix Servidor de correo saliente y de transferencia de mensajes. Permite enviar y recibir correos mediante SMTP. SMTP, puerto 25; envío autenticado comúnmente en 587.
Dovecot Servidor de correo entrante. Permite que los usuarios lean sus buzones desde clientes como Thunderbird. IMAP, puerto 143; IMAPS, puerto 993; POP3, puerto 110.
Maildir Formato de almacenamiento donde cada correo se guarda como archivo dentro del directorio del usuario. Usado por Postfix para guardar mensajes y por Dovecot para leerlos.
Thunderbird Cliente de correo que permite comprobar gráficamente el envío y recepción de mensajes. IMAP/POP3 para recibir y SMTP para enviar.

Escenario de laboratorio

Esta guía está pensada para una máquina virtual con Debian 12. La práctica usa el usuario local juan como cuenta de correo de prueba. En un escenario de producción se requiere configuración adicional de dominio, DNS, certificados SSL/TLS, antispam, antivirus, SPF, DKIM y DMARC.

1. Actualizar el sistema

Antes de instalar los servicios de correo, se actualizan los repositorios y paquetes del sistema.

1.1
Actualiza la lista de paquetes disponibles desde los repositorios configurados.
sudo apt update
1.2
Instala las actualizaciones disponibles de los paquetes ya instalados.
sudo apt upgrade -y

2. Instalar Postfix y Dovecot

Postfix funcionará como servidor SMTP para enviar y recibir mensajes. Dovecot permitirá acceder a los buzones mediante IMAP y POP3.

Nota: Durante la instalación de Postfix, selecciona Sitio de Internet. En nombre de correo del sistema puedes usar localhost o un dominio de laboratorio como correo.local.
2.1
Instala Postfix y los componentes principales de Dovecot para IMAP y POP3.
sudo apt install postfix dovecot-core dovecot-imapd dovecot-pop3d -y

3. Verificar el estado de los servicios

Después de la instalación, se revisa si los servicios quedaron activos correctamente.

3.1
Muestra el estado actual del servicio Postfix.
sudo systemctl status postfix
3.2
Muestra el estado actual del servicio Dovecot.
sudo systemctl status dovecot

4. Habilitar servicios al inicio del sistema

Esto permite que Postfix y Dovecot inicien automáticamente cada vez que Debian arranque.

4.1
Habilita Postfix para iniciar automáticamente.
sudo systemctl enable postfix
4.2
Habilita Dovecot para iniciar automáticamente.
sudo systemctl enable dovecot

5. Configurar el formato Maildir en Postfix

Maildir guarda los mensajes en carpetas individuales dentro del directorio personal del usuario. Es un formato recomendado para prácticas con Dovecot.

5.1
Indica a Postfix que almacene los correos en la carpeta Maildir del usuario.
sudo postconf -e 'home_mailbox = Maildir/'
5.2
Reinicia Postfix para aplicar el cambio.
sudo systemctl restart postfix

6. Crear la estructura Maildir para el usuario juan

Se crea la carpeta de buzón donde se almacenarán los mensajes recibidos por el usuario.

6.1
Crea la estructura básica de Maildir para el usuario juan.
sudo mkdir -p /home/juan/Maildir/{cur,new,tmp}
6.2
Asigna la propiedad de la carpeta Maildir al usuario juan.
sudo chown -R juan:juan /home/juan/Maildir
6.3
Restringe el acceso al buzón para proteger los mensajes del usuario.
sudo chmod -R 700 /home/juan/Maildir

7. Configurar Dovecot para usar Maildir

Se edita la configuración principal de Dovecot para que lea los buzones en formato Maildir.

Nota: Busca la línea mail_location. Si está comentada con #, elimínalo y deja el valor exactamente como se muestra en el punto 7.2.
7.1
Abre el archivo de configuración de ubicación de buzones.
sudo nano /etc/dovecot/conf.d/10-mail.conf
7.2
Línea que debe quedar configurada dentro del archivo 10-mail.conf.
mail_location = maildir:~/Maildir

8. Configurar autenticación básica en Dovecot

Para esta práctica se utilizarán usuarios locales de Linux como cuentas de correo.

Nota: Esta configuración es aceptable para laboratorio local. En producción debe usarse SSL/TLS y mayor endurecimiento de seguridad.
8.1
Abre el archivo de configuración de autenticación.
sudo nano /etc/dovecot/conf.d/10-auth.conf
8.2
Permite autenticación en texto plano para pruebas locales de laboratorio.
disable_plaintext_auth = no
8.3
Habilita los mecanismos de autenticación plain y login.
auth_mechanisms = plain login

9. Revisar protocolos habilitados en Dovecot

Se confirma que Dovecot tenga habilitados los protocolos IMAP y POP3.

9.1
Abre la configuración general de Dovecot.
sudo nano /etc/dovecot/dovecot.conf
9.2
Línea sugerida para habilitar IMAP, POP3 y LMTP.
protocols = imap pop3 lmtp

10. Reiniciar Dovecot

Después de modificar la configuración, se reinicia Dovecot.

10.1
Reinicia el servicio Dovecot.
sudo systemctl restart dovecot
10.2
Verifica que Dovecot esté activo y sin errores.
sudo systemctl status dovecot

11. Enviar un correo local de prueba

Para probar Postfix, se puede enviar un mensaje local al usuario juan.

11.1
Instala herramientas básicas para enviar correos desde terminal.
sudo apt install mailutils -y
11.2
Envía un mensaje de prueba al usuario juan.
echo 'Correo de prueba desde Postfix en Debian 12' | mail -s 'Prueba Postfix' juan

12. Verificar si el mensaje llegó al buzón

Se revisa la carpeta Maildir del usuario para comprobar si el mensaje fue recibido.

12.1
Lista los mensajes nuevos recibidos por el usuario juan.
sudo ls -l /home/juan/Maildir/new
12.2
Muestra el contenido del mensaje recibido.
sudo cat /home/juan/Maildir/new/*

13. Verificar puertos de correo

Se revisan los puertos usados por Postfix y Dovecot.

13.1
Verifica si Postfix está escuchando en el puerto SMTP 25.
sudo ss -tulpn | grep master
13.2
Verifica si Dovecot está escuchando en puertos IMAP o POP3.
sudo ss -tulpn | grep dovecot

14. Configurar Thunderbird como cliente de correo

Thunderbird puede usarse como cliente para probar la lectura de correos mediante Dovecot y el envío mediante Postfix.

14.1
Cambia al directorio temporal para descargar el instalador oficial de Thunderbird.
cd /tmp
14.2
Descarga el instalador oficial de Thunderbird.
wget https://download.mozilla.org/?product=thunderbird-latest&os=linux64&lang=es-ES -O thunderbird.tar.bz2
14.3
Extrae el paquete descargado.
tar -xjf thunderbird.tar.bz2
14.4
Mueve la carpeta a /opt para instalación global.
sudo mv thunderbird /opt/
14.5
Crea un enlace simbólico para ejecutar Thunderbird desde terminal.
sudo ln -s /opt/thunderbird/thunderbird /usr/bin/thunderbird
14.6
Ejecuta Thunderbird.
thunderbird
14.7
Dato de configuración para recibir correo mediante Dovecot.
Servidor entrante IMAP: localhost, puerto 143, usuario juan
14.8
Dato de configuración para enviar correo mediante Postfix.
Servidor saliente SMTP: localhost, puerto 25, usuario juan
14.9
Usa la contraseña asignada al crear el usuario con adduser.
Contraseña: la contraseña del usuario Linux juan

15. Comandos útiles de diagnóstico

Estos comandos ayudan a revisar errores y registros del sistema de correo.

15.1
Muestra los últimos registros del servicio Postfix.
sudo journalctl -u postfix -n 50 --no-pager
15.2
Muestra los últimos registros del servicio Dovecot.
sudo journalctl -u dovecot -n 50 --no-pager
15.3
Muestra en tiempo real el registro general de correo, si está disponible.
sudo tail -f /var/log/mail.log
15.4
Muestra la configuración activa y modificada de Postfix.
postconf -n
15.5
Muestra la configuración activa y modificada de Dovecot.
doveconf -n

Conclusión didáctica

Postfix y Dovecot trabajan juntos para construir un servidor de correo funcional. Postfix se encarga del envío y transferencia de mensajes mediante SMTP, mientras que Dovecot permite que los usuarios consulten sus buzones mediante IMAP o POP3. En un laboratorio local, esta configuración permite comprender la arquitectura básica de un sistema de correo electrónico en Linux.

Servicio Rol Ejemplo en la práctica
Postfix Envía y entrega mensajes Recibe el correo enviado a juan y lo guarda en Maildir.
Dovecot Permite leer mensajes Thunderbird se conecta a Dovecot para mostrar el buzón de juan.
Thunderbird Cliente de correo Permite probar visualmente el envío y recepción de mensajes.
