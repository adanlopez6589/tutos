Datos generales

Vas a construir desde cero una LAN pequeña con 2 switches y 2 PCs, configurar los switches por consola y comprobar que todos los equipos se comunican.

Material: Cisco Packet Tracer 8.x, archivo nuevo en blanco (File → New).
Tiempo estimado: 50 minutos.

Parte 1. Armar la topología

Al terminar esta parte tendrás 4 equipos en el área de trabajo, con su nombre visible.

  1. Abre Packet Tracer y crea un archivo nuevo (File → New). Guárdalo como Practica_Switch_TuNombre.pkt.
  2. En la barra inferior izquierda, entra a Network Devices → Switches.
  3. Arrastra 2 switches 2960 al área de trabajo, uno a la izquierda y otro a la derecha.
  4. Entra a End Devices → End Devices y arrastra 2 PC (PC-PT). Coloca una debajo de cada switch.
  5. Cambia el nombre visible de cada equipo: clic en el equipo → pestaña Config → Display Name:
    • Switch izquierdo: Class-A
    • Switch derecho: Class-B
    • PC izquierda: Student-1
    • PC derecha: Student-2
Importante: el Display Name es solo la etiqueta del diagrama. El nombre real del switch (hostname) se configura después por CLI.

Topología esperada

Parte 2. Conexiones UTP y de consola

Vas a hacer 5 conexiones: 3 de datos (UTP) y 2 de consola. Todos los cables están en Connections (ícono del rayo ⚡), en la barra inferior izquierda.

Tabla de cableado

1Copper Straight-Through (línea negra continua)Student-1 (FastEthernet0)Class-A (FastEthernet0/1)Equipos distintos: PC ↔ switch
2Copper Straight-ThroughStudent-2 (FastEthernet0)Class-B (FastEthernet0/1)Equipos distintos: PC ↔ switch
3Copper Cross-Over (línea negra punteada)Class-A (GigabitEthernet0/1)Class-B (GigabitEthernet0/1)Equipos iguales: switch ↔ switch

Cómo conectar cada cable

  1. Selecciona el tipo de cable en Connections.
  2. Da clic en el primer equipo y elige el puerto de la columna "Desde".
  3. Da clic en el segundo equipo y elige el puerto de la columna "Hacia".
  4. Repite para los 5 cables.

Comprueba las luces de enlace

  • Verde en ambos extremos: el enlace está activo.
  • Naranja en un puerto del switch: el puerto está negociando (STP). Espera unos 30 segundos o presiona Fast Forward Time (abajo a la derecha).
  • Rojo: cable equivocado o puerto apagado. Borra el cable y vuelve a conectarlo.
  • El cable de consola no muestra luces; es normal.
Nota de diseño: el enlace entre switches va por los puertos Gigabit porque concentra el tráfico de todos los equipos. Los puertos FastEthernet se reservan para los equipos finales.

Parte 3. Configurar el switch Class-A por consola

Entra a Class-A desde la PC Student-1 por el cable de consola y aplica nombre, contraseñas, banner, IP y guardado.

3.1 Abrir la sesión de consola

  1. Da clic en Student-1 → pestaña Desktop → Terminal.
  2. Deja los valores por defecto (9600, 8, None, 1, None) y da OK.
  3. Presiona Enter. Debe aparecer Switch>.
  4. Si te pregunta Would you like to enter the initial configuration dialog? [yes/no], escribe no.
Si la pantalla queda en negro sin prompt, revisa que el cable de consola vaya de RS 232 a Console.

3.2 Comandos

enable
configure terminal
hostname Class-A
enable secret 6EBUp
line console 0
 password xAw6k
 login
 exit
line vty 0 15
 password xAw6k
 login
 exit
service password-encryption
banner motd #Acceso solo a personal autorizado#
interface vlan 1
 ip address 10.10.10.100 255.255.255.0
 no shutdown
 end
copy running-config startup-config

Cuando aparezca Destination filename [startup-config]?, presiona Enter.

3.3 Qué hace cada comando

ComandoFunción
enablePasa del modo usuario (>) al modo privilegiado (#)
configure terminalEntra al modo de configuración global
hostname Class-ACambia el nombre del switch
enable secret 6EBUpProtege el modo privilegiado con contraseña cifrada (MD5)
line console 0 + password + loginPide contraseña al entrar por consola
line vty 0 15 + password + loginPide contraseña al entrar por Telnet/SSH (16 líneas)
service password-encryptionCifra las contraseñas que estaban en texto plano
banner motd #...#Mensaje que aparece al conectarse
interface vlan 1 + ip addressAsigna la IP de administración del switch
no shutdownActiva la interfaz VLAN 1
copy running-config startup-configGuarda la configuración en la NVRAM para que sobreviva a un reinicio

Parte 4. Configurar el switch Class-B

Repite el procedimiento entrando desde Student-2 → Desktop → Terminal. Solo cambian el nombre y la IP.

enable

enable secret 6EBUp
line console 0

 exit
line vty 0 15

interface vlan 1
 ip address 10.10.10.150 255.255.255.0

Presiona Enter para confirmar el guardado.

Comprueba el acceso: escribe exit hasta salir y presiona Enter. Debe aparecer el banner y luego pedirte la contraseña de consola (xAw6k). Después, enable debe pedirte la contraseña secreta (6EBUp).

Parte 5. Configurar la IP de las PCs

Cada PC recibe una IP estática de la red 10.10.10.0/24. No necesitan gateway porque todos los equipos están en la misma red.

  1. Da clic en Student-1 → Desktop → IP Configuration.
  2. Selecciona Static.
  3. Escribe IPv4 Address 10.10.10.4 y Subnet Mask 255.255.255.0.
  4. Deja Default Gateway y DNS Server vacíos.
  5. Cierra la ventana; los cambios se guardan solos.
  6. Repite en Student-2 con IPv4 Address 10.10.10.5 y Subnet Mask 255.255.255.0.

Parte 6. Verificación y evidencias

La práctica está completa cuando los 6 pings responden y los comandos show muestran la configuración esperada. Toma captura de pantalla de cada prueba.

6.1 Comandos en cada switch

show running-config
show ip interface brief
  • En show running-config, las contraseñas de línea deben aparecer como password 7 ... (cifradas) y el secreto como enable secret 5 ....
  • En show ip interface brief, Vlan1 debe mostrar su IP y el estado up / up.

6.2 Pings (Desktop → Command Prompt)

El primer ping puede perder 1 paquete mientras se resuelve ARP; es normal.

Preguntas de reflexión

  1. ¿Por qué se usa cable cruzado entre los switches y cable directo entre PC y switch?
  2. ¿Cuál es la diferencia entre enable password y enable secret? ¿Cuál es más seguro y por qué?
  3. ¿Qué tipo de cifrado aplica service password-encryption y por qué se considera débil?
  4. ¿Para qué le sirve una dirección IP a un switch de capa 2 si los switches no necesitan IP para reenviar tramas?
  5. ¿Qué diferencia hay entre running-config y startup-config?
  6. ¿Por qué el enlace entre switches debería ir por puertos Gigabit y no FastEthernet?
  7. ¿Qué pasaría con los pings si Student-2 tuviera la máscara 255.255.0.0?
