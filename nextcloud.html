Nextcloud con Nginx, PHP y PostgreSQL

Referencia de laboratorio · Administración y Configuración Cliente/Servidor

Esta guía instala Nextcloud, una nube privada de archivos, en Debian 12. Nginx atiende el navegador, PHP-FPM ejecuta Nextcloud y PostgreSQL guarda sus datos. Al final tendrás Nextcloud en http://localhost/nextcloud.

Qué vas a instalar

Nextcloud es una nube privada de archivos, parecida a Google Drive, que se instala en tu propio servidor. Necesita tres servicios trabajando juntos:

ComponenteFunción en la práctica
NginxRecibe las peticiones del navegador y entrega los archivos estáticos (CSS, JS, imágenes).
PHP-FPMEjecuta el código PHP de Nextcloud. Nginx le pasa las peticiones .php por un socket.
PostgreSQLGuarda usuarios, permisos y la información de los archivos.
/var/www/html/nextcloudCarpeta con el código de Nextcloud.

1. Instalar dependencias

1.1

Actualizar el sistema

Actualizar la lista de paquetes y los paquetes instalados.

$sudo apt update
$sudo apt upgrade -y
1.2

Instalar Nginx, PHP y herramientas

Nginx como servidor web, PHP-FPM con las extensiones que pide Nextcloud, y utilidades para descargar y descomprimir.

$sudo apt install nginx php php-fpm php-pgsql php-cli php-curl php-gd php-xml php-zip php-mbstring php-intl php-bcmath php-imagick php-gmp unzip curl wget gnupg2 -y
$ls /run/php/

Debe aparecer php8.2-fpm.sock. Es el socket que se usa en la configuración de Nginx del paso 4.2; si tu versión es otra, ajústala ahí.

2. Instalar y configurar PostgreSQL

2.1

Instalar PostgreSQL

En Debian 12 se instala la versión 15.

$sudo apt install postgresql -y
2.2

Entrar a la consola de PostgreSQL

Se entra como el usuario postgres, administrador de la base de datos.

$sudo -u postgres psql

El prompt cambia a postgres=#. Los comandos del siguiente paso se escriben ahí.

2.3

Crear la base de datos y el usuario

Base de datos nextcloud y usuario nextclouduser con permisos sobre ella. Cambia la contraseña por una tuya y anótala.

postgres=#CREATE DATABASE nextcloud;
postgres=#CREATE USER nextclouduser WITH PASSWORD 'tu_password_segura';
postgres=#GRANT ALL PRIVILEGES ON DATABASE nextcloud TO nextclouduser;
postgres=#\c nextcloud
postgres=#GRANT ALL PRIVILEGES ON SCHEMA public TO nextclouduser;
postgres=#\q

\c nextcloud cambia a la base nueva. El permiso sobre el esquema public es necesario desde PostgreSQL 15: sin él, Nextcloud no puede crear sus tablas. \q sale de la consola.

La configuración de PostgreSQL (/etc/postgresql/15/main/) no se modifica: Nextcloud y la base de datos están en la misma VM y se conectan por localhost.

3. Descargar Nextcloud

3.1

Descargar y descomprimir

Descargar la última versión desde el sitio oficial en una carpeta temporal.

$cd /tmp
$wget https://download.nextcloud.com/server/releases/latest.zip
$unzip -q latest.zip
3.2

Mover y asignar permisos

Copiar Nextcloud a la carpeta web y entregarla al usuario www-data, con el que trabajan Nginx y PHP.

$sudo mv /tmp/nextcloud /var/www/html/
$sudo chown -R www-data:www-data /var/www/html/nextcloud
$sudo chmod -R 755 /var/www/html/nextcloud

Si /var/www/html/nextcloud ya existe de un intento anterior, bórrala antes con sudo rm -rf /var/www/html/nextcloud.

4. Configurar Nginx

4.1

Liberar el puerto 80

Apache y Nginx no pueden usar el puerto 80 al mismo tiempo. Si Apache está instalado, se detiene.

$sudo systemctl stop apache2

⚠ Mientras Apache esté detenido no funcionan las apps instaladas con él (WordPress, PrestaShop). Al reiniciar la VM Apache vuelve a arrancar y Nginx falla; para alternar usa los comandos del paso 7.2.

4.2

Crear el sitio de Nextcloud

Crear un archivo nuevo con la configuración de Nginx para /nextcloud.

$sudo nano /etc/nginx/sites-available/nextcloud

/etc/nginx/sites-available/nextcloud

server {
    listen 80;
    server_name localhost;

    root /var/www/html;
    index index.php index.html;

    client_max_body_size 512M;
    fastcgi_buffers 64 4K;

    # Nextcloud usa archivos .mjs; Nginx de Debian 12 no los reconoce
    include mime.types;
    types { text/javascript mjs; }

    access_log /var/log/nginx/nextcloud_access.log;
    error_log /var/log/nginx/nextcloud_error.log;

    # Carpetas internas que no deben verse desde el navegador
    location ~ ^/nextcloud/(?:build|tests|config|lib|3rdparty|templates|data)(?:$|/) {
        return 404;
    }
    location ~ ^/nextcloud/(?:\.|autotest|occ|issue|indie|db_|console) {
        return 404;
    }

    location /nextcloud/ {
        try_files $uri $uri/ /nextcloud/index.php$request_uri;
    }

    location ~ ^/nextcloud/.+?\.php(?:$|/) {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
    }

    location ~* ^/nextcloud/.+\.(?:css|js|mjs|svg|gif|png|jpg|ico|wasm|woff2?|map)$ {
        try_files $uri /nextcloud/index.php$request_uri;
        access_log off;
        expires 6M;
    }
}

El bloque de .php pasa las peticiones a PHP-FPM, incluidas rutas como /nextcloud/index.php/apps/files. Los bloques que regresan 404 impiden descargar desde el navegador la configuración y los archivos de los usuarios.

4.3

Activar el sitio y aplicar

Crear el enlace en sites-enabled, revisar la sintaxis y reiniciar Nginx.

$sudo ln -s /etc/nginx/sites-available/nextcloud /etc/nginx/sites-enabled/
$sudo nginx -t
$sudo systemctl restart nginx

Resultado esperado de nginx -t: syntax is ok y test is successful. Si marca error, indica el archivo y la línea.

5. Configurar PHP

5.1

Ajustar límites de PHP

Aumentar memoria, tamaño de subida y tiempo de ejecución para manejar archivos grandes.

$sudo nano /etc/php/8.2/fpm/php.ini

Busca cada línea con Ctrl+W y cambia su valor:

memory_limit = 512M
upload_max_filesize = 512M
post_max_size = 512M
max_execution_time = 360

Estas líneas ya existen en el archivo. Cambia el valor; no las agregues repetidas al final.

5.2

Aplicar

Reiniciar PHP-FPM para que lea los nuevos valores.

$sudo systemctl restart php8.2-fpm

6. Finalizar la instalación

6.1

Abrir el asistente

Desde el navegador de la VM.

Navegador

http://localhost/nextcloud/
6.2

Llenar el asistente

Crea la cuenta de administrador de Nextcloud y conecta la base de datos del paso 2.

CampoValor
Cuenta de administradorUsuario y contraseña que tú elijas. Es distinta del usuario de la base de datos.
Carpeta de datosDeja la que propone.
Base de datosPostgreSQL
Usuario de la basenextclouduser
Contraseña de la basetu_password_segura (la del paso 2.3)
Nombre de la basenextcloud
Servidorlocalhost

La instalación tarda uno o dos minutos. Al terminar entras al panel de Nextcloud.

7. Diagnóstico

7.1

Errores comunes

Síntoma y qué revisar.

SíntomaQué revisar
502 Bad GatewayPHP-FPM detenido o socket distinto: sudo systemctl status php8.2-fpm y ls /run/php/.
Nginx no arranca: Address already in useApache sigue usando el puerto 80 (paso 4.1).
404 en /nextcloudEl sitio no está en sites-enabled o Nextcloud no está en /var/www/html/nextcloud.
Página en blanco o sin estilosFalta la línea types { text/javascript mjs; } en la configuración de Nginx.
Error de base de datos en el asistenteContraseña distinta a la del paso 2.3, o falta el permiso sobre el esquema public.
Versión de PHP no soportadaLa última versión de Nextcloud ya no admite PHP 8.2. Descarga una versión anterior desde download.nextcloud.com/server/releases/.
$sudo tail -n 30 /var/log/nginx/nextcloud_error.log
$sudo journalctl -u php8.2-fpm -n 30 --no-pager
7.2

Alternar entre Apache y Nginx

Para volver a tus apps de Apache, o regresar a Nextcloud.

$sudo systemctl stop nginx && sudo systemctl start apache2

Activa Apache (WordPress, PrestaShop).

$sudo systemctl stop apache2 && sudo systemctl start nginx

Activa Nginx (Nextcloud).

Para ver el estado de los tres servicios: systemctl status nginx php8.2-fpm postgresql.
