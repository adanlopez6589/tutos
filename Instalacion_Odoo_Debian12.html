Instalación y configuración básica de Odoo Community en Debian 12

Aplicación empresarial open source desarrollada en Python para instalar en servidor propio.

Propósito de la práctica

Instalar y ejecutar Odoo Community en Debian 12 utilizando PostgreSQL, Python, Git y un servicio systemd, con el fin de comprender el despliegue de una aplicación empresarial Python en un servidor propio.

Conceptos clave

Odoo es una suite de aplicaciones empresariales que integra módulos como CRM, ventas, inventario, compras, contabilidad, punto de venta, sitio web, comercio electrónico, proyectos y recursos humanos.

Odoo Community es la edición open source. Puede instalarse en un servidor propio y permite trabajar con módulos comunitarios o desarrollos personalizados.

ERP (Enterprise Resource Planning) es un sistema de planificación de recursos empresariales. Su propósito es integrar procesos de una organización en una sola plataforma.

PostgreSQL es el sistema gestor de base de datos utilizado por Odoo para almacenar usuarios, módulos, productos, ventas, inventarios y demás información empresarial.

Python es el lenguaje principal del backend de Odoo. El servidor de Odoo se ejecuta desde el archivo odoo-bin.

Git permite descargar el código fuente oficial de Odoo desde GitHub y seleccionar una versión específica mediante ramas como 19.0 o 18.0.

systemd permite ejecutar Odoo como servicio del sistema para iniciar, detener, reiniciar y habilitar su arranque automático.

Arquitectura básica de despliegue

Capa Componente Función
Cliente Navegador web Accede a Odoo mediante HTTP en el puerto 8069.
Aplicación Odoo Ejecuta los módulos empresariales y la interfaz web.
Lenguaje Python Ejecuta el servidor y la lógica del sistema.
Base de datos PostgreSQL Almacena la información de Odoo.
Sistema operativo Debian 12 Proporciona los servicios, paquetes y seguridad del servidor.

Flujo de solicitud

Cliente/Navegador → Odoo en puerto 8069 → PostgreSQL → Respuesta al navegador

Nota: Esta práctica instala Odoo Community desde código fuente para fines didácticos. En producción también puede agregarse Nginx como proxy inverso, HTTPS, firewall, respaldos y configuración avanzada.

1. Actualizar el sistema

Antes de instalar Odoo se actualizan los repositorios y paquetes del sistema.

1.1
Actualiza la lista de paquetes disponibles desde los repositorios configurados.
sudo apt update
1.2
Instala las actualizaciones disponibles del sistema.
sudo apt upgrade -y

2. Instalar dependencias principales

Odoo requiere Python, Git, PostgreSQL, Node.js y varias librerías de compilación para instalar sus dependencias.

2.1
Instala herramientas base, Python, PostgreSQL, Git, Node.js y librerías necesarias.
sudo apt install git python3 python3-pip python3-venv python3-dev build-essential wget curl nodejs npm libxml2-dev libxslt1-dev libldap2-dev libsasl2-dev libpq-dev libjpeg-dev zlib1g-dev libffi-dev libssl-dev postgresql postgresql-client -y
2.2
Verifica la versión de Python instalada. Odoo requiere Python 3.10 o superior.
python3 --version
2.3
Instala rtlcss, utilizado para generar estilos en idiomas con escritura de derecha a izquierda.
sudo npm install -g rtlcss
Nota: Si solo se usará Odoo en español, rtlcss no se observará directamente en la práctica, pero forma parte de las dependencias comunes del ecosistema Odoo.

3. Crear el usuario del sistema para Odoo

Se recomienda no ejecutar Odoo con el usuario root. Por ello se crea un usuario de sistema llamado odoo.

3.1
Crea el usuario del sistema odoo y su directorio personal en /opt/odoo.
sudo adduser --system --home=/opt/odoo --group odoo
3.2
Verifica que se haya creado el usuario odoo.
id odoo

4. Crear el usuario de PostgreSQL para Odoo

Odoo se conecta a PostgreSQL con un usuario propio. Este usuario debe poder crear bases de datos.

4.1
Crea el usuario de PostgreSQL llamado odoo con permiso para crear bases de datos.
sudo -u postgres createuser -s odoo
4.2
Verifica que PostgreSQL esté activo.
sudo systemctl status postgresql
Nota: El usuario de Linux odoo y el usuario de PostgreSQL odoo tienen el mismo nombre para simplificar la conexión local.

5. Descargar el código fuente de Odoo Community

El código fuente se descargará en /opt/odoo/odoo-server utilizando Git.

5.1
Cambia al usuario odoo para trabajar dentro de su directorio.
sudo su - odoo -s /bin/bash
5.2
Descarga Odoo Community desde GitHub. Se usa la rama 19.0 como versión estable reciente.
git clone https://github.com/odoo/odoo.git --depth 1 --branch 19.0 /opt/odoo/odoo-server
5.3
Entra a la carpeta donde quedó descargado Odoo.
cd /opt/odoo/odoo-server
Nota: Si se desea trabajar con Odoo 18, se puede cambiar --branch 19.0 por --branch 18.0.

6. Crear y activar el entorno virtual de Python

El entorno virtual permite instalar las dependencias de Odoo de forma aislada.

6.1
Crea un entorno virtual llamado odoo-venv dentro de /opt/odoo.
python3 -m venv /opt/odoo/odoo-venv
6.2
Activa el entorno virtual.
source /opt/odoo/odoo-venv/bin/activate
6.3
Actualiza pip, setuptools y wheel dentro del entorno virtual.
pip install --upgrade pip setuptools wheel

7. Instalar dependencias Python de Odoo

Las dependencias de Python están definidas en el archivo requirements.txt del proyecto Odoo.

7.1
Instala los paquetes Python requeridos por Odoo.
pip install -r /opt/odoo/odoo-server/requirements.txt
7.2
Comprueba que el ejecutable de Python usado pertenece al entorno virtual.
which python
Nota: Si ocurre un error de compilación, normalmente falta alguna librería del sistema. Revisa el mensaje de error e instala la dependencia indicada.

8. Crear carpeta para módulos personalizados

Además de los módulos oficiales, Odoo permite agregar módulos propios o comunitarios.

8.1
Crea una carpeta para módulos personalizados.
mkdir /opt/odoo/custom-addons
8.2
Muestra la estructura principal creada para Odoo.
ls -la /opt/odoo
8.3
Sal del usuario odoo para volver al usuario administrador.
exit

9. Instalar wkhtmltopdf para reportes PDF

Odoo utiliza wkhtmltopdf para generar reportes PDF como facturas, cotizaciones y documentos imprimibles.

9.1
Instala dependencias gráficas comunes para wkhtmltopdf.
sudo apt install xfonts-75dpi xfonts-base fontconfig libxrender1 libjpeg62-turbo -y
9.2
Instala wkhtmltopdf desde los repositorios de Debian.
sudo apt install wkhtmltopdf -y
9.3
Verifica la versión instalada de wkhtmltopdf.
wkhtmltopdf --version
Nota: Para producción, Odoo recomienda usar una versión compatible de wkhtmltopdf que soporte encabezados y pies de página en reportes. Para laboratorio, la versión del repositorio suele ser suficiente para probar el funcionamiento general.

10. Crear archivo de configuración de Odoo

El archivo de configuración define el usuario de base de datos, el puerto, las rutas de módulos y la contraseña maestra.

10.1
Crea el archivo de configuración principal de Odoo.
sudo nano /etc/odoo.conf
10.2
Agrega el siguiente contenido. Cambia la contraseña maestra por una propia.
[options] admin_passwd = CambiaEstaClaveMaestra db_host = False db_port = False db_user = odoo db_password = False addons_path = /opt/odoo/odoo-server/addons,/opt/odoo/custom-addons xmlrpc_port = 8069 logfile = /var/log/odoo/odoo.log
10.3
Crea la carpeta de logs de Odoo.
sudo mkdir /var/log/odoo
10.4
Asigna la propiedad de la carpeta de logs al usuario odoo.
sudo chown odoo:odoo /var/log/odoo
10.5
Protege el archivo de configuración para que solo root y odoo puedan leerlo.
sudo chown odoo:odoo /etc/odoo.conf && sudo chmod 640 /etc/odoo.conf
Nota: La contraseña admin_passwd no es la contraseña de acceso a Odoo. Es la clave maestra para crear, respaldar o eliminar bases de datos desde el administrador web.

11. Probar Odoo manualmente

Antes de crear el servicio systemd, se recomienda ejecutar Odoo manualmente para comprobar que inicia correctamente.

11.1
Cambia al usuario odoo.
sudo su - odoo -s /bin/bash
11.2
Activa el entorno virtual de Odoo.
source /opt/odoo/odoo-venv/bin/activate
11.3
Ejecuta Odoo usando el archivo de configuración.
/opt/odoo/odoo-server/odoo-bin -c /etc/odoo.conf
11.4
Abre Odoo desde el navegador del servidor o desde otra computadora de la red.
http://localhost:8069
11.5
Para detener Odoo en la terminal, presiona Ctrl + C y después sal del usuario odoo.
exit
Nota: En la primera entrada al navegador se crea la base de datos de Odoo. Se debe indicar la contraseña maestra definida en admin_passwd.

12. Crear un servicio systemd para Odoo

El servicio permite iniciar Odoo automáticamente y administrarlo con systemctl.

12.1
Crea el archivo de servicio de Odoo.
sudo nano /etc/systemd/system/odoo.service
12.2
Agrega el siguiente contenido al archivo odoo.service.
[Unit] Description=Odoo Community Documentation=https://www.odoo.com/documentation After=network.target postgresql.service [Service] Type=simple User=odoo Group=odoo ExecStart=/opt/odoo/odoo-venv/bin/python3 /opt/odoo/odoo-server/odoo-bin -c /etc/odoo.conf Restart=always [Install] WantedBy=multi-user.target
12.3
Recarga systemd para reconocer el nuevo servicio.
sudo systemctl daemon-reload
12.4
Inicia el servicio de Odoo.
sudo systemctl start odoo
12.5
Habilita Odoo para que inicie automáticamente con el sistema.
sudo systemctl enable odoo
12.6
Verifica el estado del servicio.
sudo systemctl status odoo

13. Acceder a Odoo desde el navegador

Una vez iniciado el servicio, Odoo debe estar disponible en el puerto 8069.

13.1
Acceso desde el mismo servidor.
http://localhost:8069
13.2
Acceso desde otra computadora de la misma red. Cambia la IP por la del servidor.
http://IP_DEL_SERVIDOR:8069
13.3
Muestra la dirección IP local del servidor.
hostname -I
Nota: Si el navegador no abre Odoo desde otra computadora, revisa firewall, conexión de red y que el puerto 8069 esté escuchando.

14. Crear la primera base de datos de Odoo

Al entrar por primera vez se muestra el administrador de bases de datos.

Campo Ejemplo Descripción
Master Password CambiaEstaClaveMaestra Contraseña definida en admin_passwd dentro de /etc/odoo.conf.
Database Name empresa_demo Nombre de la base de datos que se creará en PostgreSQL.
Email admin@empresa.local Usuario administrador inicial de Odoo.
Password Una contraseña segura Contraseña para ingresar al panel de Odoo.
Language Spanish / Español Idioma de la interfaz.
Country Mexico País para configurar opciones regionales.
Nota: El usuario administrador de Odoo no es el mismo que el usuario Linux ni el usuario PostgreSQL. Es una cuenta interna de la aplicación.

15. Comandos útiles de diagnóstico

Estos comandos ayudan a revisar errores, puertos y registros del servicio.

15.1
Verifica si Odoo está activo.
sudo systemctl status odoo
15.2
Muestra los últimos registros generados por Odoo.
sudo tail -n 80 /var/log/odoo/odoo.log
15.3
Muestra los registros de systemd asociados al servicio Odoo.
sudo journalctl -u odoo -n 80 --no-pager
15.4
Verifica si el puerto 8069 está escuchando.
sudo ss -tulnp | grep :8069
15.5
Reinicia Odoo después de modificar la configuración.
sudo systemctl restart odoo
15.6
Revisa las bases de datos existentes en PostgreSQL.
sudo -u postgres psql -c "\l"

16. Instalar Nginx como proxy inverso opcional

En producción, lo más común es publicar Odoo mediante Nginx en el puerto 80 o 443 y dejar Odoo funcionando internamente en el puerto 8069.

16.1
Instala Nginx.
sudo apt install nginx -y
16.2
Crea el archivo de configuración del sitio para Odoo.
sudo nano /etc/nginx/sites-available/odoo
16.3
Configuración básica de Nginx para reenviar solicitudes a Odoo.
server { listen 80; server_name localhost; proxy_read_timeout 720s; proxy_connect_timeout 720s; proxy_send_timeout 720s; location / { proxy_pass http://127.0.0.1:8069; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } }
16.4
Habilita el sitio de Odoo.
sudo ln -s /etc/nginx/sites-available/odoo /etc/nginx/sites-enabled/
16.5
Opcional: elimina el sitio predeterminado de Nginx para evitar conflictos.
sudo rm /etc/nginx/sites-enabled/default
16.6
Verifica que la configuración de Nginx no tenga errores de sintaxis.
sudo nginx -t
16.7
Reinicia Nginx.
sudo systemctl restart nginx
16.8
Abre Odoo mediante Nginx usando el puerto HTTP normal.
http://localhost
Nota: Si se usa Nginx, es recomendable agregar proxy_mode = True en /etc/odoo.conf y reiniciar Odoo.

17. Detener y desactivar servicios si se requiere

Estos comandos pueden utilizarse para detener temporalmente Odoo o desactivar el arranque automático.

17.1
Detiene el servicio de Odoo.
sudo systemctl stop odoo
17.2
Desactiva el inicio automático de Odoo.
sudo systemctl disable odoo
17.3
Desactiva el sitio de Nginx creado para Odoo.
sudo rm /etc/nginx/sites-enabled/odoo
17.4
Reinicia Nginx después de desactivar el sitio.
sudo systemctl restart nginx

Conclusión didáctica

Odoo permite observar una aplicación empresarial Python instalada en un servidor propio. En esta práctica se identifica la relación entre sistema operativo, lenguaje de programación, base de datos, servicio del sistema y acceso web. A diferencia de una aplicación Flask mínima, Odoo ya incluye módulos empresariales listos para activar, por lo que es útil para prácticas de servidores, bases de datos, ERP, CRM, inventarios y despliegue de aplicaciones web.

Odoo Aplicación empresarial Ejecuta módulos de ventas, inventario, CRM, sitio web y más.

PostgreSQL Base de datos Almacena las bases de datos creadas desde el administrador web.
systemd Administrador de servicios Permite iniciar, detener, reiniciar y habilitar Odoo.
