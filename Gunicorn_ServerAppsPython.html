Instalación y configuración básica de Gunicorn en Debian 12

Servidor de aplicaciones Python WSGI para ejecutar aplicaciones Flask en laboratorio.

Propósito de la práctica

Instalar y ejecutar una aplicación web básica en Debian 12 utilizando Flask y Gunicorn, con el fin de comprender la función de un servidor de aplicaciones dentro de la arquitectura cliente-servidor y su relación con un servidor web como Nginx.

Conceptos clave

Gunicorn significa Green Unicorn. Es un servidor HTTP WSGI para aplicaciones Python. Su función principal es ejecutar aplicaciones desarrolladas con frameworks como Flask o Django en un entorno más adecuado que el servidor de desarrollo incluido por Flask.

Flask es un microframework de Python que permite crear aplicaciones web de forma sencilla. En esta práctica se usa una aplicación mínima para comprobar el funcionamiento de Gunicorn.

WSGI (Web Server Gateway Interface) es una especificación que permite la comunicación entre un servidor de aplicaciones Python y una aplicación web. Gunicorn usa WSGI para comunicarse con Flask.

Entorno virtual es una carpeta aislada donde se instalan las dependencias de un proyecto Python sin afectar el sistema global. En esta práctica se utiliza un entorno llamado gunicorn_env.

Proxy inverso es la función que puede cumplir Nginx cuando recibe las solicitudes del navegador y las reenvía internamente a Gunicorn. Esto permite que Nginx atienda el tráfico web público, archivos estáticos y HTTPS, mientras Gunicorn ejecuta la aplicación Python.

Arquitectura de despliegue

En una instalación profesional, Gunicorn normalmente no se expone directamente al usuario final. Primero se coloca un servidor web como Nginx, que funciona como intermediario.

Capa Componente Función
Cliente Navegador web Solicita la página mediante HTTP o HTTPS.
Servidor web Nginx Recibe la solicitud, sirve archivos estáticos y puede reenviar la petición a Gunicorn.
Servidor de aplicaciones Gunicorn Ejecuta la aplicación Python mediante WSGI.
Framework Flask Contiene las rutas, vistas y lógica de la aplicación.

Flujo de solicitud

Cliente/Navegador → Nginx → Gunicorn → Flask → Respuesta al navegador

Nota: Esta práctica primero ejecuta Gunicorn directamente en el puerto 8000 para facilitar la comprensión. Al final se incluye una configuración opcional con Nginx como proxy inverso.

1. Actualizar el sistema

Antes de instalar las herramientas necesarias, se actualizan los repositorios y los paquetes del sistema.

1.1
Actualiza la lista de paquetes disponibles desde los repositorios configurados.
sudo apt update
1.2
Instala las actualizaciones disponibles de los paquetes ya instalados.
sudo apt upgrade -y

2. Instalar Python, pip y herramientas para entornos virtuales

Gunicorn trabaja con aplicaciones Python, por lo que se requiere Python 3, pip y el módulo venv.

2.1
Instala Python 3, pip y la herramienta para crear entornos virtuales.
sudo apt install python3 python3-pip python3-venv -y
2.2
Verifica la versión de Python instalada.
python3 --version

3. Crear la carpeta del proyecto

La aplicación se guardará en una carpeta de trabajo. La tilde (~) representa el directorio personal del usuario actual, por ejemplo /home/juan.

3.1
Crea una carpeta llamada gunicorn_test dentro del directorio personal del usuario.
mkdir ~/gunicorn_test
3.2
Entra a la carpeta del proyecto.
cd ~/gunicorn_test
3.3
Muestra la ruta absoluta de la carpeta actual para confirmar la ubicación.
pwd

4. Crear y activar el entorno virtual

El entorno virtual permite instalar Flask y Gunicorn de forma aislada para este proyecto.

4.1
Crea un entorno virtual llamado gunicorn_env.
python3 -m venv gunicorn_env
4.2
Activa el entorno virtual. Al activarse, la terminal mostrará el nombre del entorno entre paréntesis.
source gunicorn_env/bin/activate
4.3
Actualiza pip dentro del entorno virtual.
pip install --upgrade pip
Nota: La aplicación no debe guardarse dentro de la carpeta gunicorn_env. El entorno virtual solo contiene Python, pip y las dependencias del proyecto.

5. Instalar Flask y Gunicorn

Flask será el framework de la aplicación y Gunicorn será el servidor de aplicaciones que la ejecutará.

5.1
Instala Flask y Gunicorn dentro del entorno virtual activo.
pip install flask gunicorn
5.2
Verifica la versión instalada de Gunicorn.
gunicorn --version
5.3
Guarda las dependencias instaladas en un archivo requirements.txt.
pip freeze > requirements.txt

6. Crear una aplicación básica con Flask

En este paso se creará una aplicación web sencilla utilizando Flask. El archivo principal de la aplicación se almacenará dentro de la carpeta principal del proyecto y fuera del entorno virtual.

Nota: El archivo miapp.py debe guardarse dentro de la carpeta principal del proyecto. Ejemplo:

/home/juan/gunicorn_test/miapp.py

También puede utilizarse la ruta abreviada:

~/gunicorn_test/miapp.py

Estructura esperada del proyecto:

6.1
Entra a la carpeta principal del proyecto donde se almacenará la aplicación Flask.
cd ~/gunicorn_test
6.2
Crea el archivo principal de la aplicación Flask.
nano miapp.py
6.3
Agrega el siguiente contenido básico al archivo miapp.py.
from flask import Flask app = Flask(__name__) @app.route("/") def home(): return "Servidor funcionando con Gunicorn" if __name__ == "__main__": app.run()
6.4
Guarda el archivo utilizando CTRL + O, presiona ENTER y después CTRL + X para salir de nano.
Archivo guardado en: ~/gunicorn_test/miapp.py
6.5
Estructura esperada del proyecto después de crear la aplicación.
gunicorn_test/ ├── gunicorn_env/ ├── miapp.py ├── templates/ └── static/

7. Ejecutar la aplicación con Flask para prueba inicial

Antes de usar Gunicorn, se puede probar que la aplicación funcione con el servidor de desarrollo de Flask.

7.1
Ejecuta la aplicación directamente con Python.
python3 miapp.py
7.2
Abre esta dirección en el navegador para comprobar la aplicación Flask.
http://localhost:5000
Nota: Para detener el servidor de Flask en la terminal, presiona Ctrl + C.

8. Ejecutar la aplicación con Gunicorn

Ahora se ejecuta la aplicación con Gunicorn. En el comando miapp:app, miapp corresponde al archivo miapp.py y app corresponde al objeto Flask creado dentro del archivo.

8.1
Ejecuta Gunicorn en el puerto 8000 escuchando en todas las interfaces de red.
gunicorn --bind 0.0.0.0:8000 miapp:app
8.2
Abre esta dirección en el navegador del mismo equipo.
http://localhost:8000
8.3
Prueba la segunda ruta de la aplicación.
http://localhost:8000/saludo
Nota: Usa http:// y no https://. Gunicorn no configura certificados SSL/TLS automáticamente. En producción, HTTPS normalmente se configura en Nginx.

9. Ejecutar Gunicorn con varios workers

Los workers son procesos que permiten atender más solicitudes. Para laboratorio se pueden usar 2 o 3 workers.

9.1
Ejecuta la aplicación con 3 workers en el puerto 8000.
gunicorn --workers 3 --bind 0.0.0.0:8000 miapp:app
9.2
Verifica procesos relacionados con Gunicorn.
ps aux | grep gunicorn

10. Probar con otro puerto

Gunicorn puede ejecutarse en otro puerto libre, por ejemplo 8080. Esto es útil si el puerto 8000 ya está ocupado.

10.1
Ejecuta Gunicorn en el puerto 8080.
gunicorn --bind 0.0.0.0:8080 miapp:app
10.2
Abre la aplicación usando el puerto 8080.
http://localhost:8080
10.3
Revisa si el puerto 8000 está ocupado por otro proceso.
sudo ss -tulnp | grep :8000

11. Crear un servicio systemd para Gunicorn

Para que Gunicorn se pueda iniciar, detener y reiniciar como servicio del sistema, se crea una unidad systemd.

Nota: Reemplaza juan por el nombre real del usuario de Linux si estás trabajando con otro usuario.
11.1
Muestra el usuario actual para identificar qué nombre usar en el servicio.
whoami
11.2
Crea el archivo de servicio para Gunicorn.
sudo nano /etc/systemd/system/gunicorn-miapp.service
11.3
Contenido sugerido para el archivo gunicorn-miapp.service. Cambia juan si tu usuario es diferente.
[Unit] Description=Servicio Gunicorn para aplicacion Flask miapp After=network.target [Service] User=juan Group=www-data WorkingDirectory=/home/juan/gunicorn_test Environment="PATH=/home/juan/gunicorn_test/gunicorn_env/bin" ExecStart=/home/juan/gunicorn_test/gunicorn_env/bin/gunicorn --workers 3 --bind 127.0.0.1:8000 miapp:app [Install] WantedBy=multi-user.target
11.4
Recarga systemd para reconocer el nuevo servicio.
sudo systemctl daemon-reload
11.5
Inicia el servicio de Gunicorn.
sudo systemctl start gunicorn-miapp
11.6
Habilita el servicio para que inicie automáticamente con el sistema.
sudo systemctl enable gunicorn-miapp
11.7
Verifica el estado del servicio.
sudo systemctl status gunicorn-miapp

12. Instalar Nginx como proxy inverso

Nginx recibirá las solicitudes web por el puerto 80 y las reenviará internamente a Gunicorn en 127.0.0.1:8000.

12.1
Instala Nginx.
sudo apt install nginx -y
12.2
Crea un archivo de configuración para la aplicación Flask.
sudo nano /etc/nginx/sites-available/miapp
12.3
Configuración básica de Nginx para reenviar solicitudes a Gunicorn.
server { listen 80; server_name localhost; location / { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } }
12.4
Habilita el sitio creando un enlace simbólico en sites-enabled.
sudo ln -s /etc/nginx/sites-available/miapp /etc/nginx/sites-enabled/
12.5
Opcional: elimina el sitio predeterminado de Nginx para evitar conflictos.
sudo rm /etc/nginx/sites-enabled/default
12.6
Verifica que la configuración de Nginx no tenga errores de sintaxis.
sudo nginx -t
12.7
Reinicia Nginx para aplicar la configuración.
sudo systemctl restart nginx
12.8
Abre la aplicación desde Nginx usando el puerto HTTP normal.
http://localhost

13. Comandos útiles de diagnóstico

Estos comandos ayudan a revisar errores, puertos y registros del servicio.

13.1
Muestra los últimos registros del servicio Gunicorn.
sudo journalctl -u gunicorn-miapp -n 50 --no-pager
13.2
Muestra en tiempo real los registros del servicio Gunicorn.
sudo journalctl -u gunicorn-miapp -f
13.3
Revisa si Nginx está activo.
sudo systemctl status nginx
13.4
Verifica qué servicios están escuchando en los puertos 80 y 8000.
sudo ss -tulnp | grep -E ':80|:8000'
13.5
Muestra los últimos errores registrados por Nginx.
sudo tail -n 50 /var/log/nginx/error.log
13.6
Reinicia el servicio de Gunicorn después de modificar la aplicación.
sudo systemctl restart gunicorn-miapp

14. Detener y desactivar servicios si se requiere

Estos comandos pueden usarse para detener temporalmente la práctica o limpiar la configuración.

14.1
Detiene el servicio de Gunicorn.
sudo systemctl stop gunicorn-miapp
14.2
Desactiva el inicio automático del servicio de Gunicorn.
sudo systemctl disable gunicorn-miapp
14.3
Desactiva el sitio de Nginx creado para la práctica.
sudo rm /etc/nginx/sites-enabled/miapp
14.4
Reinicia Nginx después de desactivar el sitio.
sudo systemctl restart nginx

Conclusión didáctica

Gunicorn permite ejecutar aplicaciones Python de manera más adecuada que el servidor de desarrollo de Flask. En esta práctica se observa la separación entre framework, servidor de aplicaciones y servidor web. Flask contiene la lógica de la aplicación, Gunicorn la ejecuta mediante WSGI y Nginx puede recibir las solicitudes públicas para reenviarlas a Gunicorn como proxy inverso.

Componente Rol Ejemplo en la práctica
Flask Framework web Define las rutas / y /saludo dentro de miapp.py.
Gunicorn Servidor de aplicaciones Ejecuta miapp:app en el puerto 8000.
Nginx Servidor web y proxy inverso Recibe solicitudes en el puerto 80 y las reenvía a 127.0.0.1:8000.
systemd Administrador de servicios Permite iniciar, detener y habilitar Gunicorn como servicio del sistema.
