Apache Tomcat en Debian 12

Referencia de laboratorio · Administración y Configuración Cliente/Servidor

Esta guía instala Apache Tomcat, un servidor de aplicaciones para Java, como servicio de Debian 12. Al final tendrás Tomcat funcionando en http://localhost:8080, listo para desplegar aplicaciones .war.

Qué es Apache Tomcat

Apache Tomcat es un servidor de aplicaciones ligero para Java. Su función principal es ejecutar aplicaciones web desarrolladas con tecnologías Java, especialmente Servlets y JSP.

Servidor de aplicaciones
Software que ejecuta la lógica de una aplicación web y responde a las solicitudes de los clientes.
Servlet
Clase Java que recibe una petición web, la procesa en el servidor y genera una respuesta, por ejemplo HTML, JSON o texto.
JSP
JavaServer Pages. Páginas web dinámicas que combinan HTML con código Java.
WAR
Web Application Archive. Archivo empaquetado con una aplicación web Java lista para desplegarse en Tomcat.

Características y relevancia

  • Es open source y muy usado en ambientes educativos y empresariales.
  • Despliega aplicaciones Java empaquetadas en formato .war.
  • Se ejecuta como servicio del sistema en Linux mediante systemd.
  • Trabaja por defecto en el puerto 8080.
  • Se integra con Nginx o Apache HTTP Server mediante proxy inverso.
  • Ayuda a comprender la arquitectura cliente-servidor en aplicaciones web.

Aunque muchos proyectos modernos usan Spring Boot con un servidor embebido (que con frecuencia es el propio Tomcat), instalarlo por separado sigue siendo útil para entender el despliegue tradicional de aplicaciones Java, la administración de servicios en Linux y la relación entre servidor web, servidor de aplicaciones y aplicación.

El ecosistema Java es común en sectores como la banca, las telecomunicaciones, el gobierno y la investigación, donde se mantienen sistemas empresariales de gran escala.

1. Actualizar el sistema

1.1

Actualizar paquetes

Antes de instalar servicios, se actualizan los repositorios y paquetes para evitar errores por dependencias antiguas.

$sudo apt update
$sudo apt upgrade -y

2. Instalar Java

2.1

Instalar el JDK

Tomcat necesita Java para ejecutarse, porque las aplicaciones que atiende están hechas con esta tecnología.

$sudo apt install default-jdk -y
2.2

Verificar Java

Comprobar que Java quedó instalado.

$java -version

En Debian 12 se instala OpenJDK 17. Tomcat 10.1 requiere Java 11 o superior.

3. Crear el usuario del servicio

3.1

Usuario tomcatuser

El servicio se ejecutará con este usuario y no como root, para que un fallo en una aplicación no comprometa todo el sistema.

$sudo useradd -m -U -d /opt/tomcat -s /bin/false tomcatuser

-d /opt/tomcat lo usa como carpeta personal y -m la crea. -s /bin/false impide iniciar sesión con este usuario.

4. Descargar Apache Tomcat

4.1

Descargar el paquete

Se descarga desde el archivo oficial de Apache en la carpeta temporal /tmp.

$cd /tmp
$wget https://archive.apache.org/dist/tomcat/tomcat-10/v10.1.28/bin/apache-tomcat-10.1.28.tar.gz

Se usa archive.apache.org porque downloads.apache.org solo conserva la versión más reciente: las anteriores se retiran y la descarga da error 404. Para instalar la versión actual, consúltala en tomcat.apache.org y cambia el número en este comando y en el paso 5.1.

5. Instalar Tomcat en /opt/tomcat

5.1

Extraer en /opt/tomcat

Se extrae el contenido del paquete en /opt/tomcat, ubicación común para software adicional del sistema.

$sudo mkdir -p /opt/tomcat
$sudo tar -xzf apache-tomcat-10.1.28.tar.gz -C /opt/tomcat --strip-components=1

-p evita el error «File exists»: la carpeta ya la creó useradd en el paso 3.1. --strip-components=1 quita la carpeta apache-tomcat-x.y.z para que los archivos queden directo en /opt/tomcat.

6. Asignar permisos

6.1

Propietario y ejecución

La carpeta pasa a tomcatuser y los scripts de arranque y apagado se marcan como ejecutables.

$sudo chown -R tomcatuser:tomcatuser /opt/tomcat
$sudo chmod +x /opt/tomcat/bin/*.sh

7. Crear el servicio systemd

7.1

Archivo del servicio

Crear un archivo nuevo que le indica a systemd cómo iniciar y detener Tomcat.

$sudo nano /etc/systemd/system/tomcat.service

/etc/systemd/system/tomcat.service

[Unit]
Description=Apache Tomcat
After=network.target

[Service]
Type=forking
User=tomcatuser
Group=tomcatuser
Environment=JAVA_HOME=/usr/lib/jvm/default-java
Environment=CATALINA_HOME=/opt/tomcat
Environment=CATALINA_BASE=/opt/tomcat
ExecStart=/opt/tomcat/bin/startup.sh
ExecStop=/opt/tomcat/bin/shutdown.sh

[Install]
WantedBy=multi-user.target

Type=forking indica que startup.sh arranca Tomcat en segundo plano y termina. JAVA_HOME apunta al Java instalado en el paso 2.

7.2

Activar el servicio

Recargar systemd para que reconozca el servicio nuevo, iniciarlo y habilitarlo al arranque.

$sudo systemctl daemon-reload
$sudo systemctl start tomcat
$sudo systemctl enable tomcat

8. Verificar el servicio

8.1

Estado y puerto

Confirmar que Tomcat está activo y escuchando en el puerto 8080.

$sudo systemctl status tomcat --no-pager
$sudo ss -tlnp | grep ':8080 '

Resultado esperado: active (running) y una línea con :8080 del proceso java.

9. Probar en el navegador

9.1

Abrir Tomcat

Si todo funciona, aparece la página inicial de Tomcat con el gato.

Navegador

http://localhost:8080

10. Diagnóstico

10.1

Errores comunes

Síntoma y qué revisar.

SíntomaQué revisar
wget: 404 Not FoundLa versión no existe en esa ruta. Usa archive.apache.org (paso 4.1).
mkdir: File existsLa carpeta ya la creó useradd. Usa mkdir -p.
status: failedRevisa el registro con el comando de abajo. Suele ser JAVA_HOME o permisos.
JAVA_HOME is not defined correctlyComprueba que exista /usr/lib/jvm/default-java con ls /usr/lib/jvm/.
Permission deniedRepite el paso 6.1: la carpeta debe ser de tomcatuser.
El navegador no cargaTomcat apenas está arrancando (espera unos segundos) o el puerto 8080 está ocupado por otro programa.
$sudo journalctl -u tomcat -n 50 --no-pager
$sudo tail -n 30 /opt/tomcat/logs/catalina.out

Para revisar el servicio en cualquier momento: sudo systemctl status tomcat.
