Instalación de MS3 Stock Management en Debian 12

Aplicación web Python Flask para gestión básica de inventario con MongoDB.

Propósito de la práctica

Instalar y ejecutar la aplicación MS3 Stock Management en un servidor Debian 12, con el fin de comprender el despliegue de una aplicación web Python Flask conectada a una base de datos NoSQL MongoDB.

Conceptos clave

MS3 Stock Management es una aplicación web educativa para control de inventario. Permite manejar productos, categorías, proveedores, usuarios, existencias y órdenes pendientes de entrada de mercancía.

Flask es un microframework de Python utilizado para crear aplicaciones web. En esta app contiene las rutas, vistas, formularios y lógica principal del sistema.

MongoDB es un sistema gestor de base de datos NoSQL orientado a documentos. A diferencia de MySQL o PostgreSQL, no trabaja principalmente con tablas, sino con colecciones y documentos en formato similar a JSON.

MongoEngine es una herramienta ODM para Python. Cumple una función parecida a un ORM, pero para MongoDB: permite trabajar con clases de Python que se guardan como documentos en la base de datos.

Entorno virtual es una carpeta aislada donde se instalan las dependencias Python de la aplicación sin afectar el sistema global.

Arquitectura de despliegue

Capa Componente Función
Cliente Navegador web Solicita la aplicación mediante HTTP.
Servidor de aplicación Flask Ejecuta las rutas, formularios y lógica del sistema de inventario.
Base de datos MongoDB Almacena usuarios, productos, categorías, proveedores y movimientos de inventario.
ODM MongoEngine Conecta las clases de Python con los documentos de MongoDB.

Flujo de solicitud

Cliente/Navegador → Flask → MongoEngine → MongoDB → Respuesta al navegador

Nota: Esta práctica se plantea para laboratorio. Primero se ejecuta con Flask en el puerto 5000. Al final se incluye una sección opcional para preparar la app con Gunicorn como servicio.

1. Actualizar el sistema

Antes de instalar la aplicación se actualizan los repositorios y paquetes del sistema.

1.1
Actualiza la lista de paquetes disponibles.
sudo apt update
1.2
Instala las actualizaciones disponibles.
sudo apt upgrade -y

2. Instalar Python y dependencias necesarias

La aplicación MS3 Stock Management está desarrollada con Python y Flask. Para ejecutarla correctamente en Debian 12 se requieren herramientas de desarrollo, compilación y bibliotecas de seguridad.

Algunas dependencias de Flask y MongoDB necesitan compilar componentes nativos durante su instalación, por lo que se instalan paquetes adicionales del sistema operativo.

Paquete Función
python3-pip Administrador de paquetes de Python utilizado para instalar librerías mediante pip.
python3-venv Herramienta para crear entornos virtuales aislados para proyectos Python.
build-essential Conjunto de compiladores y herramientas necesarias para compilar módulos nativos.
python3-dev Archivos de desarrollo y cabeceras necesarias para compilar extensiones de Python.
libffi-dev Biblioteca utilizada por módulos relacionados con cifrado y autenticación.
libssl-dev Biblioteca de desarrollo para conexiones seguras SSL/TLS y funciones criptográficas.
Nota: Estas herramientas son comunes en servidores Linux utilizados para desplegar aplicaciones Flask, Django y otros servicios Python.
2.1
Instala Python 3 y las dependencias necesarias para ejecutar y compilar módulos de la aplicación.
sudo apt install python3 python3-pip python3-venv git unzip build-essential python3-dev libffi-dev libssl-dev pkg-config -y
2.2
Verifica la versión instalada de Python.
python3 --version

3. Instalar MongoDB Community en Debian 12

MongoDB es una base de datos NoSQL desarrollada principalmente en C++. Aunque no está programada en JavaScript, utiliza estructuras de datos similares a objetos JSON, lo que facilita su integración con aplicaciones web modernas desarrolladas en JavaScript y Node.js.

JSON (JavaScript Object Notation) es un formato ligero de intercambio de datos derivado de la sintaxis de objetos de JavaScript. Se utiliza para representar información mediante pares clave-valor.

Ejemplo de objeto JSON

{ "nombre": "Juan", "edad": 20, "carrera": "Informática" }

MongoDB almacena información utilizando documentos BSON, que es una versión binaria optimizada de JSON.

3.1
Instala herramientas para importar la llave del repositorio oficial de MongoDB.
sudo apt install gnupg curl -y
3.2
Importa la llave pública de MongoDB 8.0.
curl -fsSL https://pgp.mongodb.com/server-8.0.asc | sudo gpg -o /usr/share/keyrings/mongodb-server-8.0.gpg --dearmor
3.3
Crea el archivo del repositorio oficial para Debian 12 Bookworm.
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-8.0.gpg ] https://repo.mongodb.org/apt/debian bookworm/mongodb-org/8.0 main" | sudo tee /etc/apt/sources.list.d/mongodb-org-8.0.list
3.4
Actualiza los repositorios incluyendo MongoDB.
sudo apt update
3.5
Instala MongoDB Community Server.
sudo apt install mongodb-org -y

4. Iniciar y verificar MongoDB

MongoDB se ejecuta como servicio del sistema mediante systemd.

4.1
Recarga systemd si el servicio aún no aparece reconocido.
sudo systemctl daemon-reload
4.2
Inicia el servicio de MongoDB.
sudo systemctl start mongod
4.3
Habilita MongoDB para que inicie automáticamente con el sistema.
sudo systemctl enable mongod
4.4
Verifica el estado del servicio.
sudo systemctl status mongod
4.5
Abre la consola de MongoDB para comprobar la conexión local.
mongosh
4.6
Dentro de mongosh, muestra las bases de datos existentes.
show dbs
4.7
Sal de la consola de MongoDB.
exit

5. Descargar la aplicación MS3 Stock Management

Se puede descargar desde GitHub o usar el archivo ZIP que ya se tenga disponible.

5.1
Entra al directorio personal del usuario.
cd ~
5.2
Clona el repositorio público del proyecto.
git clone https://github.com/thanh-cao/ms3-stock-management.git
5.3
Entra a la carpeta del proyecto.
cd ~/ms3-stock-management
5.4
Confirma que existan los archivos principales de la aplicación.
ls
Alternativa con ZIP: Si ya se tiene el archivo ms3-stock-management-main.zip, súbelo al servidor, descomprímelo con unzip ms3-stock-management-main.zip y entra a la carpeta descomprimida.

6. Crear y activar el entorno virtual

El entorno virtual contendrá las dependencias de Python necesarias para esta aplicación.

6.1
Crea un entorno virtual llamado ms3_env dentro del proyecto.
python3 -m venv ms3_env
6.2
Activa el entorno virtual.
source ms3_env/bin/activate
6.3
Actualiza pip, setuptools y wheel dentro del entorno virtual.
pip install --upgrade pip setuptools wheel

7. Instalar dependencias de la aplicación

El proyecto incluye un archivo requirements.txt con las librerías necesarias.

7.1
Instala las dependencias indicadas por el proyecto.
pip install -r requirements.txt
7.2
Si aparece error con bson, desinstala bson externo para evitar conflicto con pymongo.
pip uninstall bson -y
7.3
Reinstala pymongo para asegurar que su paquete bson interno quede correcto.
pip install --force-reinstall pymongo==3.12.0
7.4
Verifica que Flask esté instalado.
python -m flask --version
Nota: El archivo requirements.txt incluye dependencias antiguas porque el proyecto original fue desarrollado con versiones de Flask y MongoEngine de 2021.

8. Crear el archivo de variables de entorno

La aplicación busca un archivo llamado env.py para cargar la conexión a MongoDB, la clave secreta y la configuración general.

8.1
Crea el archivo env.py dentro de la carpeta principal del proyecto.
nano env.py
8.2
Agrega esta configuración básica para trabajar con MongoDB local.
import os os.environ.setdefault('IP', '0.0.0.0') os.environ.setdefault('PORT', '5000') os.environ.setdefault('SECRET_KEY', 'cambia_esta_clave_en_produccion') os.environ.setdefault('MONGO_URI', 'mongodb://127.0.0.1:27017/stockmgmt') os.environ.setdefault('MONGO_DBNAME', 'stockmgmt') os.environ.setdefault('DEBUG', 'True') # Variables de correo. En laboratorio se pueden dejar vacías si se desactiva confirmación por correo. os.environ.setdefault('MAIL_SERVER', '') os.environ.setdefault('MAIL_PORT', '587') os.environ.setdefault('MAIL_USERNAME', '') os.environ.setdefault('MAIL_PASSWORD', '') os.environ.setdefault('USER_EMAIL_SENDER_EMAIL', '')
8.3
Guarda el archivo en nano con CTRL + O, ENTER y CTRL + X.
Archivo guardado en: ~/ms3-stock-management/env.py

9. Ajustar la configuración para laboratorio sin correo SMTP

El proyecto original solicita confirmación por correo al registrar usuarios. Para laboratorio puede desactivarse esa dependencia y permitir que el registro funcione sin configurar Gmail u otro servidor SMTP.

9.1
Abre el archivo config.py para modificar la configuración de Flask-User.
nano config.py
9.2
Cambia estas dos líneas dentro de ConfigClass para desactivar el envío y confirmación de correo.
USER_ENABLE_EMAIL = False USER_ENABLE_CONFIRM_EMAIL = False
9.3
Guarda los cambios en nano con CTRL + O, ENTER y CTRL + X.
Archivo modificado: config.py
Nota: En producción sí conviene configurar correo real para recuperación, confirmación de cuentas y notificaciones. Para una primera práctica, desactivarlo reduce la dificultad.

10. Ejecutar la aplicación con Flask

Con MongoDB activo, dependencias instaladas y variables configuradas, se puede ejecutar la app.

10.1
Asegúrate de estar en la carpeta del proyecto.
cd ~/ms3-stock-management
10.2
Activa el entorno virtual si no está activo.
source ms3_env/bin/activate
10.3
Ejecuta la aplicación.
python app.py
10.4
Abre esta dirección en el navegador del mismo equipo.
http://localhost:5000
10.5
Si accedes desde otra computadora de la misma red, usa la IP del servidor.
http://IP_DEL_SERVIDOR:5000
Nota: Para detener Flask en la terminal, presiona CTRL + C.

11. Registrar el primer usuario administrador

Al entrar por primera vez, se debe crear una cuenta. La aplicación crea el negocio y asigna permisos de administrador al usuario registrado.

11.1
Abre la página principal de la aplicación.
http://localhost:5000
11.2
Selecciona la opción de registro o Sign up.
Crear cuenta de negocio y usuario administrador
11.3
Después del registro, accede al panel y comienza creando categorías, proveedores y productos.
Dashboard → Categories → Suppliers → Products

12. Consultar la base de datos desde MongoDB

Estos comandos permiten observar cómo se crean las colecciones y documentos conforme se usa la aplicación.

12.1
Abre la consola de MongoDB.
mongosh
12.2
Selecciona la base de datos de la aplicación.
use stockmgmt
12.3
Muestra las colecciones creadas.
show collections
12.4
Consulta algunos documentos de usuarios.
db.user.find().pretty()
12.5
Consulta algunos productos registrados.
db.product.find().pretty()
12.6
Sal de mongosh.
exit

13. Opción adicional: ejecutar con Gunicorn

Para acercarse más a un despliegue real, la app puede ejecutarse con Gunicorn en lugar del servidor de desarrollo de Flask.

13.1
Instala Gunicorn dentro del entorno virtual.
pip install gunicorn
13.2
Ejecuta la app con Gunicorn en el puerto 8000.
gunicorn --bind 0.0.0.0:8000 app:app
13.3
Abre la aplicación ejecutada con Gunicorn.
http://localhost:8000
Nota: En el comando app:app, el primer app corresponde al archivo app.py y el segundo app corresponde al objeto Flask creado dentro del archivo.

14. Opción adicional: crear servicio systemd para Gunicorn

Con systemd se puede iniciar, detener y habilitar la aplicación como servicio del sistema.

Nota: Reemplaza juan por el usuario real de Linux. Puedes identificarlo con el comando whoami.
14.1
Muestra el usuario actual.
whoami
14.2
Crea el archivo del servicio.
sudo nano /etc/systemd/system/ms3-stock.service
14.3
Contenido sugerido para el servicio. Cambia juan si tu usuario es diferente.
[Unit] Description=MS3 Stock Management Flask App After=network.target mongod.service [Service] User=juan Group=www-data WorkingDirectory=/home/juan/ms3-stock-management Environment="PATH=/home/juan/ms3-stock-management/ms3_env/bin" ExecStart=/home/juan/ms3-stock-management/ms3_env/bin/gunicorn --workers 3 --bind 127.0.0.1:8000 app:app Restart=always [Install] WantedBy=multi-user.target
14.4
Recarga systemd.
sudo systemctl daemon-reload
14.5
Inicia el servicio.
sudo systemctl start ms3-stock
14.6
Habilita el inicio automático.
sudo systemctl enable ms3-stock
14.7
Verifica el estado del servicio.
sudo systemctl status ms3-stock

15. Comandos útiles de diagnóstico

Estos comandos ayudan a revisar errores, puertos y servicios.

15.1
Revisa si MongoDB está activo.
sudo systemctl status mongod
15.2
Muestra los últimos registros de MongoDB.
sudo tail -n 50 /var/log/mongodb/mongod.log
15.3
Verifica qué servicios escuchan en los puertos 5000, 8000 y 27017.
sudo ss -tulnp | grep -E ':5000|:8000|:27017'
15.4
Muestra los últimos registros del servicio systemd de la app.
sudo journalctl -u ms3-stock -n 50 --no-pager
15.5
Reinicia la app si se modificó código o configuración.
sudo systemctl restart ms3-stock

16. Detener servicios y limpiar la práctica

Estos comandos pueden usarse para detener la app o MongoDB cuando se termine la práctica.

16.1
Detiene el servicio de la aplicación si fue creado.
sudo systemctl stop ms3-stock
16.2
Deshabilita el inicio automático de la app.
sudo systemctl disable ms3-stock
16.3
Detiene MongoDB temporalmente.
sudo systemctl stop mongod
16.4
Elimina la base de datos de laboratorio desde mongosh si se requiere reiniciar los datos.
mongosh --eval "use stockmgmt; db.dropDatabase();"

Conclusión didáctica

MS3 Stock Management es más simple que Odoo para una primera práctica porque permite observar una aplicación Python Flask real, con formularios, autenticación, CRUD e integración con base de datos, sin entrar todavía a la complejidad de un ERP empresarial completo.

Flask Framework web Ejecuta las rutas definidas en app.py.

MongoEngine ODM Conecta las clases de models.py con MongoDB.
Gunicorn Servidor de aplicaciones Ejecuta app:app en el puerto 8000.
